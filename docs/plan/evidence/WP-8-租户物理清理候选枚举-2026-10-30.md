调度、生产部署或真实生产租户删除已经批准或完成。

## 一、实现范围

- 新增 `migrations/0061_tenant_purge_candidates.sql`；`migrations-test/0061_tenant_purge_candidates.sql`
  保持与生产迁移同源。
- 新增固定函数 `public.tenant_purge_candidates(bigint)`：只接受 `1..5000` 的候选上限，
  固定 `READ COMMITTED`、`SECURITY DEFINER`、`VOLATILE`、`PARALLEL UNSAFE` 和
  `search_path = pg_catalog, pg_temp`。
- 函数 owner 为 `tenant_purge_batcher`；`PUBLIC` 撤销 `EXECUTE`，仅 `tenant_purge`
  持有不可转授的 `EXECUTE`。
- 函数只返回按租户 id 升序排列的候选 id；过滤条件固定为
  `status = 'deleted'`、`deleted_at IS NOT NULL`、`deleted_at <= statement_timestamp() - interval '30 days'`。
- A8 精确放行完整签名，C17 增加唯一性、返回类型、函数属性、owner、正文哈希和精确 ACL 检查。
- `tenant_purge` 仍不持有根表或任何列级直接读取权限；未修改 `tenant_purge_batch`、
  `tenant_purge_finalize` 或既有迁移。

### 2.2 受限行为测试

命令：

```bash
TGM_TEST_PG_PORT=55434 \
DATABASE_URL=postgres://postgres:pw@127.0.0.1:55434/tgm \
  cargo test -p tgm-db --test tenant_purge -- --nocapture
```

结果：`10 passed / 0 failed`。新增 PURGE-5 覆盖：

- 只返回到期 `deleted` 租户，排除 `active`、`suspended`、未到期、无 `deleted_at` 和不存在租户；
- 结果按租户 id 升序，`limit=1` 只返回一个候选；
- `limit=0` 和 `limit=5001` 失败；
- 连接角色确认为 `tenant_purge` 且非 `BYPASSRLS`；
- `tenant_purge` 不能直接 `SELECT id FROM tenants`。
