# WP-2-remaining R2-A：身份失去授权时通知租户

日期：2026-10-22。提案：`docs/plan/proposals/WP-2-remaining.md` §R2-A 细化（2026-10-22 第二次批准）。

## 判据

spec/08 §五：身份转入 `unauthorized` / `banned` 时要做三件事——释放租约、通知租户、写 `audit_logs`。
在此之前，第 2 条（通知租户）没有实现。`USER_DEACTIVATED*` 原来被归入 `unauthorized`，按提案拆分出来，改判为 `banned`。

## 落地

- 迁移 `migrations/0024_tenant_notifications.sql`：甲类表，带 RLS 三件套；`app_user` 只有 `SELECT, INSERT, UPDATE` 和序列 `USAGE`，没有 `DELETE`。
- 测试库补丁 `migrations-test/0025_test_support_notifications.sql`：给 `tgm_test` 补表权限和 `tgm_test_admin` 策略。0014 只覆盖它运行时已经存在的表，所以要单独补。
- 库层 `crates/db/src/repo.rs`：新增 `mark_leased_identity_lost`，在同一个持租约事务里完成转状态、释放租约、写 `identity.unauthorized|banned` 审计、入队，四步一起成功或一起回滚。`mark_bot_sender_unauthorized` 同样会入队。`record_tenant_notification` 只推进 `PENDING` 的行。
- 错误判定 `crates/tg/src/client.rs`：新增 `is_banned()`，匹配 `USER_DEACTIVATED*`；`is_unauthorized()` 不再包含这一类。worker 与 delivery 的匹配点都补了 banned 分支。
- 发送循环 `crates/app/src/tenant_notify.rs`：control-plane 启动时拉起，默认 30s 一轮，每个租户每轮最多 20 条，经控制 Bot 私聊 `tenants.owner_user_id`。
  - 403 / 400：置 DEAD，不重试。
  - 429、5xx、网络错误：按 60s×2^n 退避，第 5 次失败后置 DEAD。
  - 文案只含身份 id，不含 session、手机号等敏感信息。
- 与提案的一处差异：提案写「未配置 `TGM_CONTROL_BOT_TOKEN` 时不启动循环」。实际上 control-plane 启动本身就要求这个 token，缺了直接拒绝启动，所以这条分支不存在。

## 测试

`crates/app/tests/tenant_notify.rs`，以 `app_user` 连接，Bot API 用 axum mock：

| 用例 | 断言 |
|---|---|
| `lost_authorization_enqueues_exactly_one_in_same_transaction` | 转 unauthorized 后恰好一条 PENDING、一条审计，租约已释放 |
| `banned_marks_status_audit_and_notification` | `banned` 状态、`identity.banned` 审计、`identity.banned` 通知 |
| `bot_sender_unauthorized_enqueues_once` | 投递侧 Bot 失效同样入队一条 |
| `delivery_sends_to_owner_once` | 发给 owner、置 SENT，下一轮不重发 |
| `forbidden_is_dead_and_not_retried` | 403 直接 DEAD，下一轮不再请求 |
| `rate_limited_backs_off_then_dead` | 429 退避重试，第 5 次后 DEAD |
| `notifications_are_tenant_isolated` | 租户 A 读不到也写不了租户 B 的通知 |

另有 L1：`tenant_notify` 的分类与退避 3 条，`client.rs` 的 `is_banned` / `is_unauthorized` 互斥断言。

## 反证

每项都是临时改一处源码、确认对应用例变红，然后恢复源码：

- 删掉 `mark_leased_identity_lost` 里的入队调用 → 入队类用例变红。
- 把 403 改成可重试 → `forbidden_is_dead_and_not_retried` 变红。
- 隔离策略改成 `USING (true)` → `notifications_are_tenant_isolated` 变红。

## 没有真机覆盖的部分

- `banned`：Telegram 封禁无法人为复现，只有 L1/L2 覆盖。
- 控制 Bot 真实私聊 owner：可选，需要控制 Bot token 和一个已私聊过 Bot 的 owner 账号。目前只有 mock Bot API 覆盖。
