# WP-2-remaining R1：在线期间撤销会话（真机）

日期：2026-10-22。提案：`docs/plan/proposals/WP-2-remaining.md` §R1。

## 判据

spec/08 §五：转入 `unauthorized` 时要释放租约、写 `audit_logs`，并且不自动重试。
`WP-2-qr-login-live-2026-10-21.md` 的 T6 只覆盖了上线前校验识别出撤销的情况。本项补的是另一条分支：身份已经 `online`，运行中被撤销。

## 做法

- 用例：`crates/app/tests/mtproto_live.rs` 的 `live_r1_revoked_while_online`（`#[ignore]`）。
- session 经 `live_user_qr_login` 扫码获得，过程中经历了 2FA 和 DC 2→5 迁移，再经生产路径 `save_session` 加密落库。
- worker 以 `auth_check_interval = 10s` 起跑，状态变为 `online` 后打出 `[R1] online, revoke now`，然后由人在手机端「设置 → 设备」终止该会话。
- 以 `app_user` 连接（`seed_with_session` 断言了 `current_user`）。

## 结果

```text
[R1] online, revoke now
[R1] exit=Unauthorized online_until_detected=20.750907151s status=unauthorized audits=1 lease_takeover=ok
test result: ok. 1 passed; 0 failed
```

- 退出原因为 `IdentityExit::Unauthorized`，`identities.status = unauthorized`。
- `identity.unauthorized` 审计恰好一条。
- 失效后另一个 worker 能立即接管租约。
- 从上线到识别共 20.75s，包含人操作手机的时间；周期校验间隔为 10s。

## 过程中排除的两次假失败

前两轮都在 600s 后超时，原因都不在 worker：

1. 第一轮被终止的不是测试会话。用测试 session 调 `account.getAuthorizations`，测试会话（`tgmonitorbot666 0.10.0`）仍是 `current=true`，而且持续活跃。worker 停在 `online` 是正确行为。
2. 第二轮的撤销发生在用例超时之后。超时后再调，返回 `401 AUTH_KEY_UNREGISTERED`，只能重新扫码再跑一轮。

两次都说明：会话真实有效期间，worker 不会误判为失效。
