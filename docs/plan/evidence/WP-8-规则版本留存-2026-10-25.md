## 一、实现与边界

- 复用 `cleanup-tenant`、`tenant_cleanup` 和专用配置，仅增加 `rule-versions` 类别与 timer 样例。
  追加幂等迁移，不改旧迁移、不新建表、角色或依赖。
- 到期期限沿用规格；当前版本和任何状态的存量任务引用均保留，停用规则当前版本不例外。
  全部状态租户参与分页清理，按每批语句可见的当前 plan 判定，不缓存套餐或回退未知值。
- 清理角色只增加键、时间、当前版本与引用键的列级读取及版本 DELETE。
  不可读取 `snapshot`、payload 或凭据，不可修改规则与任务；固定清理日志仍与删除同事务提交。
- 共用入队入口先持版本类别共享事务锁，清理持同键排他锁。
  等待后用后续语句复查版本，已有幂等任务优先返回，不重建任务或 `random_id`。
  两侧实际检查 READ COMMITTED；不支持的隔离级别失败，不假定所有部署都使用默认配置。
- 旧计划引用的版本已消失时，整批新任务与事件处理标记回滚，由 worker 退避后重新读取规则。
  当前版本本身缺少快照属于数据不一致，停止而非持续重试；NotFound 不泛化为可重试。
  具体入队错误通过共用事务实现保留，不把数据库错误或新错误码暴露给客户端。
- 显式删除规则仍删除其版本历史，不取消已入队任务。锁协议约束共用应用入口，
  不证明任意直接 SQL 下的并发引用完整性；RLS 的直接 SQL 测试与应用并发测试分别留证。

## 二、定向验证与反证

`crates/db/tests/rule_version_retention.rs` 的受限连接覆盖分档期限、当前及停用当前版本、
各任务状态引用、跨租户同键、直接 SQL 权限、套餐变更、限批、日志失败及取消后重跑。
现有 cutoff 检查增加版本类别，精确到期可删、下一微秒保留。
`C9` 定向反证增加版本引用键漏授、快照多授和当前版本列转授；原 `C8` SQL 未改。

清理与入队使用两个独立连接，以真实锁等待同步：入队先持锁时清理跳过，任务提交后版本保留；
清理先提交时旧版本不可入队，先写的其他任务也回滚，事件仍可重新处理。
显式删除规则后的重复入队仍返回原任务，`random_id` 不变。

应用测试覆盖语义更新、替换复制推进版本后重新计划，以及首次加载快照前版本消失的恢复路径。
另验当前快照缺失时 worker 退出、不写任务、不标记事件已处理；停止信号可结束正常 worker。
这些测试使用本地数据库，不读取真实 Telegram 或 AWS 凭据。

实际移除共享锁后，`enqueue_first_blocks_cleanup_until_task_is_visible` 失败；
跳过版本存在性复查后，`cleanup_first_invalidates_entire_enqueue_and_allows_replan` 失败。
两项均确认测试实际执行并命中断言，而非因编译错误报红；反证结束源码逐字节恢复。
日志为 `mutations.log`、`without-shared-lock.log` 和 `without-version-recheck.log`。

初轮定向测试因测试 payload 不满足既有 CHECK、日志失败探针校验了已有日志而失败；
修正种子及使用 NOT VALID 的受控约束后通过。新增应用测试另因 SQL 字符串生命周期编译失败，
收紧为静态 SQL 后实际执行通过。失败日志保留，不记为产品门禁通过。
