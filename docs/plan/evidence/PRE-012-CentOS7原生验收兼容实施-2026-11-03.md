## 一、实现与范围核对

- `scripts/verify-native-candidate.py` 仅移除 Python 3.6 不支持的 future 导入；签名身份、
  issuer、清单、包内外元数据及 provenance 校验逻辑未删减。
- 原生预检按 `systemd-analyze --help` 判断 `calendar` 能力；不支持时仍由目标 `verify`
  解析 timer，核对返回状态及诊断。缺少 timer、缺少或为空的 `OnCalendar` 均拒绝；有独立
  `calendar` 的环境继续运行日历检查，不在失败后回落到旧路径。
- cleanup 和应用路径复用 unit 检查。只对本次 unit 名匹配未知、忽略、无效及不支持的
  配置诊断；其他宿主 unit 的警告保留显示。模板名兼容实例名诊断。
- 包含地址族限制的 unit 要求 systemd 声明 `+SECCOMP`；`-SECCOMP`、能力信息缺失或
  相似但不是该特征的字符串均拒绝。版本与构建特征输出，RPM 可用时追加包版本。
- 没有修改 unit、安装参数、稳定链接、签名身份、workflow、迁移、工程卡口或生产配置。
  README 说明依赖与拒绝条件，backlog 维持 active。
