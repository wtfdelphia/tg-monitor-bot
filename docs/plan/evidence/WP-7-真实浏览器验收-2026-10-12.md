## 实现与实测问题

新增 `crates/app/tests/console_browser.rs` 和 `console_browser.js`。复用 SQLx 独立
测试库、既有测试种子、受限连接池、会话签发 Repo 和控制面 Router，监听地址只绑定
本地回环。业务与鉴权请求分别使用 `app_user`、`auth_lookup`，测试显式核对角色。
注入管理池只准备数据和检查最终结果，不用于处理浏览器请求。

Node 子进程从标准输入接收临时会话，不继承数据库连接串。浏览器访问真实页面与
真实 HTTP API，没有替换页面脚本或返回 mock API 成功响应。唯一请求暂停发生在
关键词新增，用于观察待提交状态与重复事件，释放后仍由真实服务处理。
请求拦截拒绝外部来源，检查 URL 查询和 JSON 请求体没有 `tenant_id`。

首次真实浏览器运行在登录页发现盒模型问题：视口宽度 390，文档宽度 407，卡片宽度
424。原卡片的宽度没有包含内边距，窄屏发生横向溢出。补全登录页 `border-box`；
控制台同时限制弹性主内容最小宽度、允许顶部操作换行、在窄屏把侧栏改为顶栏，
缩小边距并限制表单控件宽度。共用表格渲染增加可横向滚动、可键盘聚焦的容器，
宽表格保留数据，不把整页撑宽；规则网格允许小于原列宽的窄屏。

没有修改认证、授权、会话算法、业务 API、Repo、迁移、RLS、GRANT、审计或 CI。
没有新增项目依赖、前端框架、生产测试入口或全局状态抽象。

## 浏览器验收

本地环境：Node `v26.5.1`、已有 Puppeteer `24.40.0`、Chrome `153.0.8010.52`。
显式运行返回 0，日志为
`/home/openclaw/wtf_workspace/local/tg-monitor-bot-release/browser-test-final.log`。
截图和反证截图保留在同目录 `browser-artifacts-final/`，不含真实账号或凭据。

- 登录页：公开可访问，390 宽度无整页溢出，键盘可达 OIDC 和扫码入口。未配置控制
  Bot 时真实服务报错，按钮恢复、挑战链接隐藏；没有调用 Telegram。
- 关键词：实际数据库返回非法正则错误后保留输入、恢复控件；随后通过键盘新增。
  请求待提交时控件锁住，重复提交事件只产生一次 POST；刷新后仍有新增数据。
  带 HTML 的测试关键词以文本展示，未执行脚本，也未生成图片请求。
- 规则：使用新增关键词与本地测试目标创建规则；批量停用，持久化条件与替换，编辑
  模板，再通过真实版本 API 查看快照。模板里的脚本字符串不执行。
- 六页布局：登录另验；身份、规则列表、新建规则、编辑规则、关键词、目标频道在
  1280、768、390、320 宽度检查整页无横向溢出、主内容宽度可用、导航焦点可达。
  规则新建与编辑属于同一页类型，均实际渲染。长名称、表单和宽表格均有测试数据。
- 布局反证：仅在浏览器内恢复登录卡片的错误盒模型、移除表格滚动限制，两次都被
  同一溢出断言抓住；撤销样式后重验通过。表格聚焦后按方向键可以滚动。
- 只读角色：真实 VIEWER 会话隐藏业务写入口，规则列表无批量选择，编辑页拒绝。
- 会话：390 宽度会话表无整页溢出；确认后撤销另一条测试会话，再退出当前会话。
  页面与 `/auth/me` 随后返回 401，管理池另核对该用户的会话已清空。

浏览器测试显式标记 `ignore`，因为默认 CI 没有约定浏览器运行环境。默认 workspace
测试跳过它不算浏览器通过；本轮通过来自带 `--ignored` 的实际运行。复跑入口：

```bash
DATABASE_URL=postgres://tgm_test:tpw@127.0.0.1:55432/tgm_test_control \
SQLX_OFFLINE=true \
TGM_BROWSER_EXECUTABLE=/usr/bin/google-chrome \
cargo test -p tgm-app --test console_browser -- --ignored --nocapture
```

须有可由 Node 解析的 Puppeteer 与可执行浏览器。默认不关闭浏览器沙箱；本地受控
环境本轮显式设置 `TGM_BROWSER_ALLOW_NO_SANDBOX=1`，不把它写入生产配置。设置
`TGM_BROWSER_ARTIFACT_DIR` 可保留截图；未设置时不在仓库写截图。
