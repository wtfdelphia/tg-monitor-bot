## 一、实现与边界

- 追加 `0032_shared_cleanup_role.sql` 和 `0033_shared_event_retention.sql`；不改旧迁移、不新建表或依赖。
  独立 `shared_cleanup` 角色只读取候选元数据、关系键和到期父事件的全局投影引用键，
  可删除原始事件、写固定平台清理日志，不能读正文、凭据、对象 key 或租户详情。
- 投影端与成员端外键改为 `NO ACTION`，组端和中转 job 保持级联。
  仍有任意租户投影或存量组关系时保留；先删除可回收组，再在后续批次处理成员。
  现有成员唯一约束仍禁止多组绑定，不以不可构造的场景冒充验收。
- 仅回收已扇出、严格超过既有期限且无引用的事件。未完成扇出、有效下载期限或无期限的下载任务均保留；
  已过期下载可回收，迟到完成回滚档案写入并沿用对象补偿删除。
- 清理取事务级作业锁，并按排序后的身份键持排他锁，再复用既有媒体组锁。
  采集、聚合、扇出、规则入队、中转认领/失败/完成的共用入口持身份共享锁。
  等待后用新语句复查，明确拒绝非 READ COMMITTED；不持事务跨外部下载。
- `tgm cleanup-shared` 持独立连接，每批删除与固定平台日志同事务。
  批间等待、重叠退出、日志失败回滚、SIGTERM 取消和重跑沿用现有清理形状；
  小批次后仍继续，直到零删除，避免组先删后漏掉成员。
- 新增 `C10` 精确权限与 `C11` 引用约束审计及双遍反证；不放宽现有断言。
  共享表不带 RLS，该角色数据库层可删除任意原始事件，TTL/限批仍由固定应用 SQL 保证。

## 二、专项验证

受限角色专项覆盖 free/pro 跨租户引用、未命中投影仍保留、在途投递任务保护、精确时间边界、
媒体组释放次序、有效/无期限/过期下载、档案不级联、全局引用完整性和近期引用键不可见。
正文多授、引用列漏授、转授、序列越权及四条外键缺失/额外危险级联均有受控反证。
放宽引用策略后近期引用会错误可见；恢复 `CASCADE` 后有引用父行可被删除，验证防线的实际作用。

并发用例观察真实数据库锁等待，验证写入先提交后引用复查、清理先提交后迟到扇出、
下载期限刷新及晚到成员绑定。应用用例验证限批、多批和组后成员续跑、互斥及取消回滚；
CLI 子进程验证独立配置、错误脱敏、行锁等待中 SIGTERM 后退出与重跑。
MinIO 用例验证清理先提交后迟到上传的档案回滚和对象补偿删除；不连接 Telegram 或生产 AWS。

初轮 SQLx 定向编译误连空测试控制库，修正为离线宏编译后通过；新增反证曾使用动态 SQL 字符串，
被 SQLx 编译期约束拒绝，改成固定 SQL 后实际执行通过。两次失败均不计作验收通过。
最终 db 定向执行包括库单测和共享留存集成用例，全部通过；完整门禁同时覆盖最新权限与额外级联反证。

## 三、隔离空库与调度

一次性 PostgreSQL 容器使用 `--network none`、tmpfs 数据和任务专属 Unix socket，
从生产路径创建角色、执行全部迁移并运行审计。种子包括可删组与成员、仍有投影、有效下载、近期和未扇出事件。
清理实际删除组与成员，保留非目标事件；日志累计计数与实际删除一致。
临时 user timer 触发同一命令，退出成功、主进程为零，随后停止并移除临时单位及容器。

首次空库验收业务检查通过，但 PostgreSQL socket 目录改成粘滞权限后导致宿主清理失败；
仅对该任务目录修正权限、清除残留后重跑，包含资源清理的整条验收成功退出。

原始 systemd 样例因本机尚未安装 `/usr/local/bin/tgm` 无法直接完成验证。
在临时 `SYSTEMD_UNIT_PATH` 中保留样例内容，仅替换二进制为本地构建路径并补最小依赖，
`systemd-analyze verify` 退出零；`hourly` 日历表达式可解析。
这不证明生产系统用户、Secret 文件、真实小时周期、告警或部署已完成。
