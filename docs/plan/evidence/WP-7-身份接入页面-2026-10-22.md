## 一、范围与实现

本片在 PR #44 合并后的 `dev`（`b15e7fe22e1e99a171363e5aa8ef7628d1693b50`）上实施。
维护人于 2026-10-22 批准提案范围，仅改现有身份页、测试与证据；
不改生产 API、QR 驱动、数据库、RLS、GRANT、KMS 权限或 CI。

身份页为所有者/管理员提供 Bot 接入、Telegram 用户账号扫码和既有 MTProto 身份重新授权。
Bot 复用 `/api/v1/identities/bot`；用户账号复用既有 QR、轮询与 2FA 端点。
读取与业务写入仍经同源 Cookie、CSRF 和原有服务端角色、套餐、租户/用户绑定校验。
页面不传租户参数，不把浏览器隐藏控件当成服务端权限控制。

Token、API Hash 和密码使用密码输入框，提交前清空，不在失败后恢复。
接入请求设置超时、`cache: no-store` 与可中止信号；失败只展示固定提示，
不渲染后端原始错误或将凭据写入 URL、日志、DOM 数据属性、浏览器持久存储。
浏览器截图检查会隐藏整个接入区，避免把二维码或尚未提交的凭据纳入证据。

代持说明展示 session 的权限范围、平台风险和 `custody-v0` 内测占位状态，
主动勾选后才提交既有授权版本，不默认同意、不升级法律文本或落库语义。
重新授权入口只列 MTProto 身份，要求原账号一致；账号一致性仍由既有服务端实现判断。

二维码经 XML 解析核对根元素与命名空间，用独立 `img` 的 SVG data URL 展示，不把 SVG 插入 HTML。
25 秒串行轮询，服务器轮换后替换图像；二维码自身过期即清图。
2FA 状态暂停轮询，密码错误保留重试入口，按后端节流下限延后下一次密码请求。
终态、离页、结束、重新发起或刷新身份列表时中止旧请求、清定时器和登录材料；
每轮代次防止旧响应覆盖当前状态。单次页面操作另设既有登录总时限。
结束本页不等于 Telegram 注销，页面明确提示服务端登录仍按已有时限过期，没有虚构取消 API。

## 二、页面脚本与反证

新增 `console_identity_intake.js`，由既有 Rust 页面脚本入口执行实际内嵌 JS，复用 Node 标准库。
检查固定角色拒绝、显式同意、CSRF/同源/no-store 请求、输入清空、重复提交互斥、
重新授权字段、QR 轮换、错误密码重试、终态和总时限、图像过期、离页中止、旧响应拒绝，
以及网络错误、429、非法 XML/过期材料不回显原始错误。

测试内存中分别破坏 Token/API Hash/密码清空、两层提交锁、同意校验、代次、定时器清理与角色拒绝，
对应检查必须失败。两层提交锁是冗余保护，反证同时移除表单入口锁与共用 `runWrite` 锁，
不把只删其中一层而仍被另一层保护误记成测试失效。反证没有写入生产文件。
已有页面脚本一并重跑通过。

## 三、真实浏览器与数据库边界

复用 `console_browser.rs` 的 SQLx 临时库、真实 Router、受限 `app_user`/`auth_lookup` 连接，
临时 Web 会话经鉴权 Repo 签发，只通过子进程标准输入交给 Node。

- Bot：浏览器输入虚构 Token，真实 HTTP handler 调本地 `getMe` 桩，
  经开发环境 `EnvKek` 加密落库，再由管理池核对密文不含 Token、`kek_id` 正确。
  不是 Telegram 或生产 KMS 验收。
- MTProto：测试 Router 外层明确替换 QR/2FA 请求为本地 HTTP 桩，
  在真实 Chrome 验图像解码、轮换、重新授权选择、错误密码与重试、输入清空和终态刷新。
  这一段没有执行真实 QR handler、Telegram 驱动、session 落库或账号匹配，不将桩当成真机。
- VIEWER：身份接入区不渲染；六页布局、关键词与规则、会话管理等既有浏览器检查继续执行。
  网络审计拒绝外部请求及租户控制参数；允许的 SVG data 图像不计为外部网络。
- 凭据受限角色、pro/授权版本门槛及未知登录拒绝由真实 `control` 集成测试重跑，
  跨租户/跨用户状态登记逻辑沿用既有 `QrLoginStore` 单测。

首次浏览器测试编译因 `sqlx::types::chrono` 不导出 `Duration` 而失败；
改用标准库 `std::time::Duration`，没有新增依赖或放宽断言。重跑已显式执行忽略的浏览器测试并通过。
之后又加强图像轮换的实际尺寸断言，并随定向测试重跑最终版本。
浏览器脚本总超时改为 180 秒，包含真实轮询等待，不修改默认 CI 的 ignored 约定。

## 五、保留事项

- 本片不等于整个 WP-7 通过。控制台登录页二维码、目标频道连通性自检仍未实现。
- `custody-v0` 仍是占位授权，正式同意文本、留存、注销和举报归后续任务，不写成合规就绪。
- 没有使用真实 Telegram、AWS 或生产凭据；没有安排用户扫码。
- 前端字符串及请求体只能尽快丢弃引用，不能承诺 JavaScript 引擎可验证地擦除所有内存副本。
- 既有 API ID/身份编号的 JSON 数字精度边界未在本片改变；不得据此声称所有 BIGINT 场景都已验。
- 尚未提交、推送或开 PR；本地验收不代替对应 PR CI。
