## 一、实现范围

- 新增 `migrations/0056_tenant_purge_finalizer.sql`，并同步
  `migrations-test/0056_tenant_purge_finalizer.sql`。
- 新增登录角色 `tenant_purge` 和独立 `NOLOGIN` 函数 owner
  `tenant_purge_finalizer`；生产业务库不授予二者任何业务角色成员关系，
  `tgm_test` 仅保留集群级 SQLx 测试转授能力，且生产库禁止其 `CONNECT`。
- 新增唯一的 `public.tenant_purge_finalize(bigint)` 入口：调用者必须是
  `tenant_purge`，函数 owner 必须是 `tenant_purge_finalizer`，固定 `READ COMMITTED`、
  `search_path = pg_catalog, pg_temp` 和生命周期 advisory lock。
- 入口重新检查 `deleted` 状态、数据库时间计算的 30 天到期条件、所有已登记残留及跨租户共享引用。
  非到期返回 `not_due`，状态不符返回 `not_deleted`，锁冲突返回 `locked`，残留返回 `blocked`。
- 仅在检查通过后删除租户根行，并在同一事务写入平台级 `tenant_purge / cleanup.done` 日志；日志失败时删除回滚。
- `tenant_purge` 不拥有根表 `DELETE`、表/序列权限、建对象权限或敏感列读取权限。
  finalizer 不拥有子表删除、`UPDATE`、`TRUNCATE` 或未批准对象权限。
- 新增 ADR-0040；同步 A8 精确放行、C16 审计、工程约定、安全规格和测试策略。

登录角色不能直接删除根表或创建对象，以及不能读取密文、会话凭据、消息正文和媒体对象 key。

### 2.2 全新探针库迁移

在现有 Compose PostgreSQL 上创建临时 `tgm_wp8_probe3` 数据库，克隆完整 schema 后删除该库的迁移账本第 56 行，
再执行：

```bash
TGM_DB_URL_OWNER=postgres://postgres:pw@127.0.0.1:55432/tgm_wp8_probe3 \
cargo run --quiet --bin tgm -- migrate

DATABASE_URL=postgres://postgres:pw@127.0.0.1:55432/tgm_wp8_probe3 \
sqlx migrate run --source migrations
```

结果：0056 首次应用成功；`sqlx migrate run` 重入成功；迁移行 `56 | tenant purge finalizer | success=true`。
探针库中 `tenant_purge` / `tenant_purge_finalizer` 无业务角色成员关系；SQLx 控制角色的集群级转授能力不进入生产连接路径。

C5 的探针前提也实际校准：撤销探针库对 `PUBLIC` 和 `tgm_test` 的 `CONNECT` 后，`tgm_test → tgm_owner`
不会被当作生产登录角色；生产库 `tgm` 保持 `tgm_test` 无 `CONNECT`。
