## 四、RLS 开关两态 EXPLAIN 对比

在一次性 PostgreSQL 数据库 `tgm_g3_explain_20261105` 中应用当前迁移，灌入合成
`source_subscriptions` 行后，对扇出热路径执行相同查询：

```sql
SELECT id
  FROM source_subscriptions
 WHERE tg_chat_id = -1000004242
   AND receiver_identity_id = 1
   AND enabled;
```

RLS 开启并设置 `app.tenant_id` 时：

```text
Index Scan using idx_subscription_fanout on source_subscriptions
  Index Cond: ((tg_chat_id = '-1000004242'::integer) AND (receiver_identity_id = 1))
  Filter: (tenant_id = (current_setting('app.tenant_id'::text))::bigint)
```

RLS 关闭时：

```text
Index Scan using idx_subscription_fanout on source_subscriptions
  Index Cond: ((tg_chat_id = '-1000004242'::integer) AND (receiver_identity_id = 1))
```

判定：`pass`。两态均使用 `idx_subscription_fanout`，RLS 开启时额外应用租户策略过滤，
未退化为全表扫描。本次一次性数据库已在验证后销毁。

## 五、执行中的环境错误

为保留可复核性，本轮没有把初次执行错误隐藏为全绿：

1. 首次直接运行 SQLx 测试时未设置 `DATABASE_URL`，测试在数据库初始化前因 `DATABASE_URL must be set` 失败；
2. 新 worktree 首次编译数据库 crate 时，`DATABASE_URL` 指向尚未迁移的 `tgm_test_control`，SQLx 在线宏检查报表不存在；
3. 按 `AGENTS.md` 注入 `SQLX_OFFLINE=true` 和仓库规定连接后，目标测试全部通过。

上述两次失败属于执行环境配置错误，不计入业务测试失败；修正后的命令和结果已在本记录第二、三节列出。
