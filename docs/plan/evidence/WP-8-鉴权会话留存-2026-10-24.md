## 一、实现范围

- 新增独立 `auth_cleanup` 登录角色与幂等权限迁移，不修改旧迁移，不加业务表。
  生产迁移不写口令，本地初始化单独预置测试口令。
- `tgm cleanup-auth --category` 只接受 `challenges`、`web-sessions`、`bot-sessions`；
  直接以专用角色登录，拒绝业务、鉴权或 owner 身份，拒绝混入其他已登记凭据。
  不初始化业务池、KMS、Telegram、Redis 或对象存储客户端。
- 清理规则引用规格原文；数据库 cutoff、完整键排序、限批删除、事务级同类互斥、
  批间等待与删除时再检查并发续期均有实现。未提交批次可中断回滚，已提交批次不撤销。
- 固定平台日志与删除同事务提交，仅含表名、行数、耗时；错误退出不输出底层 SQL 或连接串。
- 新增 `C8` 权限精确白名单与双遍反证；覆盖列级漏授/多授、MAINTAIN、序列权限和转授权限。
  双遍恢复快照补齐角色属性、序列及授权转授位；定义文档与执行 SQL 同步。
- 提供独立系统用户、独立环境文件的 systemd 样例及部署步骤。

`console_login_challenges` 保持丙类、不开 RLS。该角色在数据库层可删除全部挑战，
仅固定应用 SQL 限制到期和批量，不能称作数据库到期隔离。
Web/Bot 会话的到期 SELECT/DELETE 策略不依赖可伪造的租户/用户 GUC。

本片不包含其他生命周期表、媒体平台日志补齐、租户注销、同意文本或举报入口；
不代表整个 WP-8 出口通过。

## 二、验证与修正

定向验证已覆盖真实受限角色删除、活跃行保留、边界、跨用户、分批、重叠、
日志写失败回滚、并发续期、权限拒绝、固定 CLI 参数与 SIGTERM 后重跑。
新增权限反证测试以 owner 身份执行测试 DDL，但清理断言始终由 `auth_cleanup` 执行。

本轮实际遇到并修正的问题保留如下，不将失败计为通过：

1. 受限测试控制角色看不到其他角色的等待事件，改为观察未授予的 `pg_locks`，
   确认清理确实等到行锁后才提交续期；不是用 sleep 猜并发。
2. 精确时间测试的初版时间字面量和 Duration 路径错误已修正；最终使用真实删除 SQL
   验证 cutoff 相等删除、晚一微秒保留，不用常量比较替代行为。
3. 扩展审计测试先因动态 SQL 未显式标记安全而编译失败；SQL 只来自编译期内嵌的审计文件，
   与现有审计执行器同样使用 `AssertSqlSafe`。随后测试 DDL 用测试控制角色执行只产生授权警告，
   没有真正制造破坏；改为测试事务内 `SET LOCAL ROLE tgm_owner` 后，漏授/多授反证通过。
4. 临时调度验收首次克隆了带测试触发器的 template1，却用了生产迁移，丙类表被提前开 RLS，
   清理变为空批；改为隔离的 template0 空库，按 `tgm migrate` 生产路径创建结构后重验。
   未修改已应用迁移或放宽生产 RLS。
5. 临时调度脚本原先把预期的服务失败当成启动异常，且同步等待阻塞了停止测试；
   分别按预期非零结果、异步启动后观察真实行锁处理。三类测试服务及专属库均在 finally 清理。
6. Chrome 在本轮前两次启动时等待调试端点超时，未据此记浏览器通过；后续结果单列。
7. 2026-10-25 完整门禁在 CLI 的 SIGTERM 测试发现退出超时：取消正在等行锁的 SQL 后，
   SQLx 默认把连接归池，归池检查仍等待该查询结束，随后 `pool.close()` 无法及时完成。
   改为每个清理批次借出连接时设置 `close_on_drop`，取消后关闭该批连接、不再归池等待；
   新增行锁未释放时停止并关闭池的应用回归，不能靠加长测试超时或先释放锁掩盖问题。
8. 增加序列授权快照后，双遍在 `A2b` 撤销发现既有遗漏：表 owner 往返切换会吞掉
   `keywords_id_seq` 给 `app_user` 的 USAGE，旧快照未覆盖序列，原撤销只恢复了表权限。
   本轮按既有迁移恢复该序列授权，补齐撤销步骤；未删除快照段或扩大审计白名单。
9. 隔离空库探针首次等待 Docker 创建容器超时；重试时发现前一次创建仍占用同名容器。
   确认并清理本任务容器后，使用已存在的镜像重跑，生产迁移、审计及三类别清理均通过。
   只调整探针启动等待，没有放宽应用断言；最终复查没有该容器或悬空卷。
