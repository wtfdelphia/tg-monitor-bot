# PRE-017：v0.1.0 的 url 公告风险裁定（2026-11-26）

任务：`pre017-v010-url-advisory-disposition-20261126`。

判据出处：`docs/plan/proposals/PRE-017-stable-release-runtime-and-advisory-followup.md`
§3.2、§6.2、§6.2.1、§五。本记录是维护人对已发布 `v0.1.0` 依赖公告
`RUSTSEC-2026-0592` 的风险处置裁定，把该提案状态块中的
`maintainer_risk_disposition=pending` 落为已记录。

## 一、裁定结论

```text
advisory=RUSTSEC-2026-0592
affected_package=url<=2.5.8
patched_version=2.5.9
published_release=v0.1.0
published_source_commit=31d1aa4a51a56512f96c10a466cbf394f10ff5cc
disposition=accept-residual-risk
disposition_recorded_by=WTFGEDelphia
disposition_recorded_at=2026-11-26
old_assets_mutation=none
fix_delivery=next-stable-version
```

1. **接受 `v0.1.0` 的残余风险**。二进制级与跨 crate 的调用可达性仍未
   证明（§三），现有检索无法判断公告所列触发路径是否存在于
   `v0.1.0` 二进制中。
2. **修复随下一个稳定版本交付**。`dev` 与 `main` 的 `Cargo.lock` 已锁定
   `url 2.5.9`；下一稳定版本的 `prepare` 必须核对 `url >= 2.5.9`、
   `cargo deny check advisories` 通过且 SBOM 反映新锁文件（PRE-017 §3.2）。
3. **旧资产保持不可变**。`v0.1.0` 的 Git tag、Release 资产、签名、
   provenance 与 SBOM 一律不原地替换、不重签、不重新发布（PRE-017 §二.3）。

## 二、裁定依据

公告原文（`rustsec/advisory-db` 的 `crates/url/RUSTSEC-2026-0592.md`，
2026-11-20）：`url 2.5.8` 及更早版本中，`Url::origin()` 处理 `blob:` URL
时把其路径按 URL 再解析并对结果递归调用自身，嵌套 `blob:` 前缀没有深度
限制；对不受信输入调用 `Url::origin()` 会栈溢出并中止整个进程，
`catch_unwind()` 无法捕获。`url::quirks::origin()` 同样经过
`Url::origin()`。修复版本 `2.5.9` 起不再自递归。

对 `v0.1.0` 的定向检索（PRE-017 §6.2.1，2026-11-25）：

- `cargo tree --locked --offline -p tgm --edges normal --invert url@2.5.8`
  确认正式二进制的正常依赖图包含 `url 2.5.8`；该 Release 的 SBOM 也记录
  `url 2.5.8`。
- 对正常依赖图中 295 个含源码的包、7,732 个 Rust 文件做文本检索，
  `Url::origin()`、`url::Url::origin()`、`url::quirks::origin()` 的显式
  调用命中为 0；命中的同名 `origin()` 分别是
  `aws-smithy-http-client` 的连接池 `OriginKey`、`aws-sdk-kms` 的
  `OriginType` builder 与 `sqlx-macros-core` 的 `ColumnOrigin`，均不是
  `url::Url`。
- 同一精确源码（`31d1aa4`）运行 `cargo deny check advisories` 因
  `RUSTSEC-2026-0592` 以退出码 1 失败；当前 `dev` 与 `main` 锁文件
  （`url 2.5.9`）运行同一检查通过。

触发条件与暴露面对照：公告的触发前提是对不受信输入调用受影响函数。
应用源码与正常依赖源码的文本检索没有发现这类调用；服务至今没有以
`v0.1.0` 或任何版本在目标机安装为生产服务（历次目标机验收记录均为
`production_services: untouched`，G5 出口复核为 `not-ready`）。

## 三、裁定的已知限制

本裁定不宣称公告路径在 `v0.1.0` 二进制中不可达。检索只覆盖锁文件正常
依赖图中可用 crate 的 `src/` 文本调用，没有构建跨 crate 调用图，没有
覆盖 `build.rs` 输出、宏展开、运行时反射或无法从源码文本识别的调用形式，
也没有对优化构建产物做动态验证（PRE-017 §6.2.1 原文限制）。本裁定基于
已归档证据接受残余风险，可达性仍未证明。

## 四、后续约束

1. 新稳定版本的 `prepare` 验收必须附本裁定引用，并核对锁文件与 SBOM
   使用 `url >= 2.5.9`、`cargo deny check advisories` 通过（PRE-017 §3.2）。
2. 不因本裁定创建新 tag、运行 `publish`、推送稳定镜像或改动 `v0.1.0`
   的任何已发布材料；稳定发布仍受 PRE-013 顺序条件与 G4 条件约束。
3. 若未来出现新的 `url` 公告或可达性反证，重新评估并按同一审批分界
   记录，不回改本文件。
