## 一、问题与实现

登录页原先在创建挑战成功后才展开提示区，创建失败的提示因此不可见。
创建和轮询没有捕获网络异常；轮询使用 `setInterval`，慢请求可能重叠，
导致错误后按钮一直禁用或同一挑战出现并发请求。

本轮只改登录页脚本与相应测试：

- 点击时先展开提示区，清除旧确认码与链接；创建失败恢复重试入口。
- 请求设置超时并捕获网络、HTTP、JSON 解析错误，不让异常逃出点击或轮询回调。
- 使用 `setTimeout` 在上一次轮询结束后安排下一次；创建和轮询期间拒绝重复点击。
- 本地或服务端过期、拒绝、未知状态及请求失败均停止轮询，只有确认成功才跳转。
- 显示 Bot 链接前校验挑战材料、过期时间、同源 Telegram 链接与 nonce 对应关系；
  确认码使用 `textContent`，不写浏览器认证 Cookie。
- 明确控制台登录不等于 Telegram 账号接入，提醒用户比对 Bot 确认码；
  若接口返回 `NOT_INVITED`，展示联系工作区管理员的提示。

复用现有 Node 标准库页面脚本检查，只提取共用的 Rust 执行入口，未新增依赖。
没有改变认证 handler、Bot 状态机、迁移、RLS、角色、GRANT、审计断言、CI 或门禁脚本。
