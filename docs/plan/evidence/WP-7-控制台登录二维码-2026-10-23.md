## 一、批准范围与实现

维护人于 2026-10-23 批准单独实施控制台登录二维码交付，并明确将浏览器请求的
`cache: no-store` 纳入本片范围。本片最初基于 PR #45 合入 `dev` 后的提交
`ad3e265803fa0ee15aa26ba7c169fb6c5e53afbe` 实施；本轮又在目标自检 PR #46 合入后的
`dev` 提交 `08c7dc80cf225e2d23c9dbbe44dcca4acdbe81c5` 上复跑。不新增迁移、表、权限、路由或依赖。

`POST /auth/qr/challenge` 复用既有 `render_qr_svg`，在写入挑战行前生成与
`deep_link` 完全一致的 `qr_svg`。响应继续由既有服务端中间件返回
`Cache-Control: no-store`，浏览器页面的挑战创建、轮询和身份接入请求也显式使用
`cache: 'no-store'`。

登录页使用独立 `<img>` 展示 SVG data URL，不把 SVG 当 HTML 插入。页面先检查 XML
根元素、命名空间、元素顺序和允许属性，拒绝脚本、外部引用、事件属性及非预期填充色。
二维码加载失败时保留已校验的深链接与确认码作为替代入口；过期、拒绝、确认、失败、
重试和离页都会清理图像、深链接、确认码及定时器。`generation` 与
`AbortController` 防止旧请求覆盖新挑战，只有 `confirmed` 才导航到控制台。
