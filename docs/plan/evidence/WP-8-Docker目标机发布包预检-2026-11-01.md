# WP-8：Docker-only 目标机发布包预检（2026-11-01）

任务 id：`WP-8-docker-release-preflight`。

本记录定义并验证目标机只使用 Docker 发布包的预检边界。目标机只需要 Docker Engine、Docker
Compose v2、Bash、`sha256sum`、`grep`、`find` 等常见 Coreutils 和发布包，不需要源码、Rust、
Cargo 或宿主机 PostgreSQL 客户端；发布包包含已构建镜像、逐文件校验值、隔离 Compose 工件、
角色初始化文件和预检脚本。

判据出处：`docs/design/ops/00-部署与运行时.md` §一至§二；
`docs/plan/proposals/WP-8-production-ops-acceptance.md` §二至§五；
`docs/plan/evidence/WP-8-未决输入与验收顺序台账-2026-10-31.md` §五。

## 一、执行边界

- 构建端负责构建、校验并导出镜像；目标机只负责 `docker load` 和运行时预检。
- 目标机不读取 Git 仓库，不执行 `cargo build`，不使用宿主机 `target/`。
- PostgreSQL 验收默认使用 `postgres:17.11-alpine3.23@sha256:05aa77262db9277fde6374bb2f901c9604b8a9373029e1a7993440c6aae48736`；
  可通过 `TGM_ACCEPTANCE_PG_IMAGE` 临时切换 `postgres:17.11-bookworm` 进行诊断，不改变生产镜像。
- 预检使用独立随机 Compose project、internal network 和 Docker 提供的 `/dev/shm` tmpfs 启动
  隔离数据库；Compose 通过显式入口包装在容器内再次设置 `PGDATA` 为
  `/dev/shm/tgm-postgres-data`，不使用宿主目录 bind mount、Docker named volume 或
  overlayfs 数据目录，避免旧内核、SELinux、user namespace 和 UID 映射阻止写入。健康后由
  验收脚本通过 `psql` 标准输入执行角色初始化 SQL。数据库数据随容器退出销毁，不产生持久化
  数据库目录。
- 只使用合成租户数据；不连接生产数据库、Redis、对象存储、Telegram、KMS 或真实备份。
- 预检结束删除本次 project 的容器和网络；PostgreSQL 数据位于容器内 `/dev/shm`，随容器退出销毁；
  已加载镜像默认保留，便于后续人工核对。
- 不启用生产 systemd timer、Docker scheduler、cron 容器或任何周期删除任务。

## 二、发布包内容

| 文件 | 作用 |
|---|---|
| `image.tar` | 已构建 Docker 镜像归档 |
| `image.id` / `image.ref` | 本机镜像 ID（诊断值）与加载后的引用 |
| `image.fingerprint` | 跨 Docker 主机核对的镜像内容指纹 |
| `source.commit` | 构建来源提交 |
| `package-files.sha256` | 发布包逐文件 SHA-256 |
| `README.md` | 目标机执行说明 |
| `deploy/docker/wp8-acceptance.compose.yaml` | 隔离 PostgreSQL 与 tgm 运行容器 |
| `scripts/init/01-roles.sql` | 合成验收角色初始化 |
| `scripts/wp8-docker-acceptance.sh` | Docker-only 迁移、审计与清理探针 |
| `scripts/wp8-docker-release-preflight.sh` | 目标机入口 |

发布包禁止出现生产 `.env`、生产数据库连接串或密码、Bot token、`api_hash`、KMS Secret、
Telegram session、二维码、源码和 Cargo 缓存。隔离 Compose 与角色初始化文件中的固定密码只
用于合成非生产 PostgreSQL，不得复用于生产。

角色初始化 SQL 由验收脚本通过 `psql` 标准输入执行；预检脚本仍保持仅所有者可执行。

## 三、预检判据

| 检查项 | 预期 |
|---|---|
| 逐文件校验 | `package-files.sha256` 全部匹配 |
| 镜像导入 | `docker load` 后镜像内容指纹与 `image.fingerprint` 一致；本机 `.Id` 只作诊断记录 |
| 运行时身份 | 非 root `10001:10001` |
| 运行时内容 | 无源码、Cargo 缓存、`.env` 和构建期 `SQLX_OFFLINE` |
| 隔离环境 | Compose project、internal network 和容器内 `/dev/shm` PostgreSQL 数据均属于本次预检 |
| 数据库路径 | 通过镜像执行 `tgm migrate`、`tgm audit-rls` |
| 清理探针 | 未到期、非 deleted、锁冲突、共享引用阻塞和非目标租户保护均通过 |
| 清理 | 本次 project 资源删除；不执行全局 prune |

## 四、不能由本预检证明的事项

- 目标机生产数据库角色、`tenant_purge` 权限和真实 `audit-rls`；
- 真实生产备份恢复、RPO/RTO、恢复副本隔离和跨副本删除策略；
- 生产对象存储、Redis、主机日志、告警和值班升级；
- Telegram 外部副本删除范围；
- 生产周期调度启用或 WP-8/G5 通过。
