## 三、执行与回显

```bash
cd <辅助目录>
python3 scripts/wp8-rocky-app-acceptance.py
```

脚本拒绝 root，检查候选安装目录中的 `VERSION` 与 `BUILDINFO.json`，启动随机命名、仅绑定
回环地址的临时 PostgreSQL、Redis 和 MinIO。六角色均执行临时 user unit 启停、身份、环境、
SIGTERM、SIGKILL 恢复、依赖失败恢复和配置拒绝检查；默认不读取 system journal，日志脱敏记为
`not-run`。如需完成日志脱敏验收，使用下方的只读 `--system-journal` 模式。

管理员在目标机验收窗口临时创建最小 sudoers 规则（将 `tgmtest` 替换为实际验收用户）：

```sudoers
# /etc/sudoers.d/tgm-acceptance-journal
tgmtest ALL=(root) NOPASSWD: /usr/bin/journalctl
```

规则文件应为 root 所有、权限 `0440`，并先用 `visudo -cf /etc/sudoers.d/tgm-acceptance-journal`
检查。该规则只允许非交互执行 `/usr/bin/journalctl`，不授予 root shell；验收结束后由管理员删除
该临时规则。脚本不打印日志正文，只按本次随机 unit 检查是否有配置敏感值泄漏。

完成六角色日志脱敏验收：

```bash
cd <辅助目录>
python3 scripts/wp8-rocky-app-acceptance.py --system-journal
```

如果只补测指定角色，可追加 `--roles control-plane bot-gateway mtproto-worker fanout rule delivery`；
`--system-journal` 权限不可用时脚本应直接失败，不会把 `not-run` 误报为通过。

默认复用当前登录用户已有的 `systemctl --user` manager；不需要执行 `systemd --user`、
`systemd-run` 或 `dbus-run-session`。如果目标机明确要求每个角色使用隔离 manager，且已确认
这两个命令可用，再显式追加 `--isolated-manager`；普通 Rocky 手工验收不要追加该选项。

运行前只检查以下非生产前提：

```bash
test "$(id -u)" != 0
command -v docker systemctl systemd-analyze journalctl python3
docker compose version
systemctl --user show-environment >/dev/null
```

脚本会自动启动随机命名的临时 Compose project。它只使用本机 Docker socket，PostgreSQL、Redis
和 MinIO 只绑定 `127.0.0.1`；不会连接生产服务，也不会读取候选安装目录之外的生产环境文件。

请完整回传输出。若失败，脚本给出脱敏原因与本次 project 名称；不要删除名称无法确认的
Docker 资源。不要发送环境文件、完整连接串、token、api_hash、session、密码或消息正文。

成功只说明六角色候选二进制的非生产运行时通过，不说明系统级清理服务、清理 timer、生产
备份恢复、跨副本删除、真实 Telegram 或 WP-8 整体通过。
