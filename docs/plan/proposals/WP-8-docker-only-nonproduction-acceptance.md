# WP-8：Docker-only 非生产验收工件提案

任务 id：`WP-8-docker-only-nonproduction-acceptance`。

状态：提案阶段，等待维护人批准。基线为 `cloud/dev` 合并提交
`960ee67d698ac8ad0915ac6b73e270618d7a5473`（PR #74）。本提案只申请增加并验证
Docker 运行工件，以 Docker 在隔离环境执行合成数据验收；不连接生产、不安装生产机器、
不启用周期清理，也不改变 WP-8 完成判据。

## 一、背景与目标

目标机器的运维约束是仅使用 Docker 安装、部署和测试。仓库已定义单个 `tgm` 二进制镜像
的生产设计，但 Dockerfile 尚未构建验证；根目录 `compose.yaml` 目前只启动本地
PostgreSQL、PgBouncer、Redis 和 MinIO，没有 `tgm` 应用服务或生产发布 Compose 文件。
租户物理清理的现行生产运行工件则是 systemd oneshot service/timer。

因此 Docker 可以承载镜像运行、迁移后的只读审计、合成探针数据检查和手动 one-shot
清理验收；单靠容器重启策略不能替代定时调度。本提案不把“容器能启动”或本地 Compose
通过写成生产运行验收。

`docs/design/ops/01-上线就绪与运维.md` §二至§六；
`docs/plan/proposals/WP-8-production-ops-acceptance.md` §二；

## 二、批准后范围

1. 增加单一 `tgm` 多阶段 Dockerfile，按部署规格使用锁定依赖构建 release 二进制，运行阶段使用非 root 用户；镜像不包含配置文件、真实凭据或构建缓存。
2. 增加独立的非生产验收 Compose 工件或等价脚本，使用隔离的 Docker 网络、独立命名卷和合成数据；不改现有本地开发 Compose 的服务语义。
3. 在隔离数据库里验证镜像帮助命令、生产迁移入口、`audit-rls` 和只针对合成探针租户的手动 `purge-deleted-tenants`。清理前验证未到期、错误状态、锁/共享引用阻塞和重跑边界；只允许销毁本次隔离项目创建的资源。
4. 验证容器以非 root 身份运行、配置通过受控环境文件注入、日志不输出连接串/凭据/消息正文，容器退出码能表示失败；记录镜像摘要和执行提交。
5. 提供明确的清理步骤，只删除本次 Compose project 创建且已核实归属的容器、网络和具名卷；禁止全局 prune。

实现时不得修改已应用迁移、放宽数据库角色权限、变更删除语义或新增生产 Secret。若发现这些改动必要，停止并另提安全/迁移提案。

## 三、明确不在本提案范围

- 不连接、读取或恢复真实生产备份；不使用真实租户、真实身份或任何生产凭据。
- 不安装镜像或 Compose 栈到生产目标机，不执行生产迁移、审计或租户删除。
- 不创建或启用 Docker scheduler、cron 容器或其他周期清理机制；生产周期任务替代 systemd 需要单独的运行架构提案，须定义单实例锁、失败告警、停机语义和恢复行为。
- 不把 Docker-only 非生产演练等同于真实生产备份恢复、生产 `tenant_purge` 角色核查、生产探针、告警验收或跨副本删除证明。
- 不宣布 WP-8 或 G5 通过。

若业务要求目标机完全没有 systemd，生产物理清理的周期触发在本提案结束后仍是未决项。可以在未有批准的生产调度方案前，将 Docker-only 主机用于手动、受控的非生产验收，但不能据此启用生产周期删除。

## 四、验收判据

1. 在 `cloud/dev` 对应提交上可重复构建 Docker 镜像，并记录镜像 digest；不依赖宿主机 `target/` 目录。
2. 运行阶段不含源码、`.env`、凭据、Cargo 缓存，且进程不是 root。
3. Compose project 使用独立网络与具名卷；启动、失败退出和清理命令均限定于该 project，不触及已有共享 Compose 栈。
4. 镜像执行 `tgm migrate` 与 `tgm audit-rls` 后，隔离数据库符合迁移和审计判据；使用受限角色的专项检查不得借 owner/超级用户旁路。
5. 物理清理仅作用于本次创建的合成探针；未到期、非 deleted、共享引用/锁阻塞均不得误报完成，阻塞解除后可安全重跑，重复执行保持幂等。
6. 任一步失败即停止后续破坏性步骤；日志脱敏，保留退出码和必要的合成数据计数，不保留敏感环境内容。
7. 演练后只清理本次新建且已确认归属的容器、网络、卷及构建产物；不得使用 `docker system prune --volumes`。
8. 按仓库要求运行适用的完整门禁，并在证据中区分静态门禁、隔离数据库验收和未执行的生产验收。

## 五、批准后交付

若批准，下一任务只实现上述 Docker 镜像与非生产验收工件，交付单独的 Docker-only 演练记录；之后仍须分别补齐生产策略输入、生产只读核验、备份恢复、生产探针、告警责任和生产调度批准。批准本提案不自动授权部署到生产主机、启用清理调度或删除任何生产租户。
