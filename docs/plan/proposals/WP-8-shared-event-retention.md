前片已经覆盖租户事件到期清理、投递任务脱钩和终态任务留存。
本片接在租户投影清理之后，处理已经没有使用者的共享原始事件，不重新实现已有媒体对象清理。

已核查的链路是：采集写入 → 媒体组聚合 → 按租户扇出 → 规则处理并标记 `matched_any`
→ 中转 job → 投递 → 租户事件留存 → 媒体对象及档案清理。
实现依据包括 `crates/db/src/repo.rs`、`crates/app/src/pipeline.rs`、
`crates/app/src/media_relay.rs`、`crates/app/src/media_cleanup.rs`，以及事件和媒体相关迁移。

现状有以下边界：

- `tenant_events.canonical_event_id` 当前为 `ON DELETE CASCADE`。误删共享事件会绕过租户事件清理入口，
  连带删除其他租户投影，并触发投递任务脱钩；前片的租户生命周期锁不能单独阻止这条路径。
- `media_group_members` 的组、成员两端均级联。成员没有直接租户投影，也可能仍被一个待投相册间接使用。
- `tenant_events` 的 RLS 会隐藏其他租户的投影。以 `app_user` 或 `tenant_cleanup` 在单个租户上下文下
  执行全局 `NOT EXISTS`，不能证明共享事件没有其他引用。
- 媒体组写入与聚合已有共同的事务级 advisory lock；必须复用，不能另建一把互不相识的锁。
- `media_relay_jobs` 随事件级联，下载在事务外进行。清理与认领、完成之间需要单独验证，不能靠持有长事务跨下载解决。
- 现有 `media_cleanup` 已覆盖对象到期、无对象且无 job 引用的旧档案、staging 孤儿回收。
  其只写 tracing、不写 `system_logs` 的缺口已登记在 `../ponytail-debt.md`，本片不冒充已修复。

## 二、本片范围与未决基线问题

本片建议先实现一个可以独立验收的范围：

1. 已完成扇出、达到既有保留期，且没有任何租户投影引用的 `canonical_events` 回收。
2. 媒体组聚合事件、成员与中转 job 的安全删除顺序、并发保护和重跑。
3. 独立最小权限清理入口、固定平台日志、每小时调度样例、审计与受限角色测试。

未命中、命中过的时间候选分别沿用 `spec/04` §一、§1.2；时间条件不取代引用检查。
仍有直接投影的事件、仍有存量组关系的成员、尚未完成扇出的事件，本片均不按年龄强删。
命中标记本身不是扇出或处理完成的证明。

**这里有一项不能隐去的未决问题：**
规格要求未命中原始事件在 24h 后物理删除，但当前规则处理会保留 `matched = FALSE` 的租户投影，
前片又按 free/pro 的事件留存期回收这些投影。若所有引用都保护，仍有未命中投影的原始事件就不能在 24h 后删除；
若直接沿用原来的级联，则会提前删除租户投影，且可能碰到未处理投影或任务。

本片选择先保护引用，**不把 24h 偷改成“有引用时按租户期限保留”，也不声称已经完整满足未命中留存规则**。
仍有已处理未命中投影的 24h 回收另行定案：建议下一片研究先回收无任务的已处理未命中投影，再回收共享事件；
批准前需明确它对租户事件可见期限的影响，按 `plan/00` §九判断是否需要新增 ADR。
不得把本次批准解释为已经批准提前删除这些投影。

本片也不处理 `tenant_notifications` 的终态期限、租户注销、凭据销毁、同意文本、举报入口，
不改对象存储的删除策略、不迁移现有媒体清理日志、不新增 Telegram 真机验收或新依赖。

## 三、建议实施方案

### 3.1 数据库约束先阻止误级联

只追加幂等迁移，不改已应用文件、不写 down：

- 将 `tenant_events.canonical_event_id` 的删除动作改为 `NO ACTION`，使仍有直接引用的共享事件不能被删除。
  保留现有外键列和索引，不新增租户列、不删除投影、不改变投递日志保留期。
- 将 `media_group_members.member_event_id` 的删除动作改为 `NO ACTION`；
  `group_event_id` 继续级联，删除无引用的聚合事件时释放组关系，成员在后续候选中回收。
  成员仍有组关系时不删除；现有 `UNIQUE(member_event_id)` 已禁止一个成员同时绑定多个组，
  本片保留该约束，不新增多组关系。
- `media_relay_jobs.canonical_event_id` 保持级联，不给清理角色单独删除 job 或档案的权限。

应用查询仍要检查直接及间接引用，外键是最后一道阻止数据丢失的防线，不拿约束异常代替正常候选筛选。
删除时若发生引用竞态，当前批次回滚；下一次事务用新快照重新取候选，不能记录虚假的删除成功。
只对已识别的约束竞态做有界重试，其他数据库错误非零退出。

本次外键变化会影响经身份删除触发的事件级联。现有 `delete_identity` 在有事件依赖时先拒绝删除，
须保留并回归该行为；将来租户物理删除必须明确跨表次序，不能依赖旧的原始事件级联。
不据此宣称租户注销已完成。

### 3.2 独立角色与全局引用可见性

建议新增仅供一次性清理进程使用的 `shared_cleanup` 登录角色，独立配置 `TGM_DB_URL_SHARED_CLEANUP`：

- 明确 NOSUPERUSER、NOBYPASSRLS、NOCREATEDB、NOCREATEROLE、NOREPLICATION；
  不属于其他角色，不拥有表、schema 或函数，不通过 `SET ROLE` 切入。
- `canonical_events` 仅 SELECT 候选时间、状态、身份/聊天/媒体组锁键所需元数据及 DELETE；
  不读正文、caption、发送者信息、`raw_file_id`，不给 INSERT、UPDATE、TRUNCATE。
- `media_group_members` 仅 SELECT 组与成员键，`media_relay_jobs` 仅 SELECT 关联键、状态及回收期限。
  不读媒体对象 key、文件名或内容，不直接写这两张表。
- `tenant_events` 仅 SELECT `canonical_event_id`，不读租户、事件正文、规则命中或任务 payload，
  不授 INSERT、UPDATE、DELETE。为本角色添加单独的 SELECT 策略，只暴露父原始事件已达到最短候选年龄的引用键；
  任何本片可删除的原始事件，其所有租户引用都必须可见，不能按当前租户或投影年龄再次过滤。
- 上述跨租户 SELECT 是明确的新权限边界，须同步规格与精确授权审计。
  不用 PUBLIC、恒真策略或等价恒真表达式绕开 A6，不使用 SECURITY DEFINER、视图或 BYPASSRLS。
- 只允许写 `tenant_id IS NULL` 的 `shared_retention/cleanup.done` 固定日志；
  context 仅含 `table`、`rows`、`elapsed_ms`，表名限定 `canonical_events`，不含任何消息、身份或租户标识。
  不授日志读取、UPDATE、DELETE 或任意平台事件写入。

角色口令由部署环境提供，迁移不写口令；业务进程不继承这个连接串。
启动时必须核对直接登录身份、角色属性与成员关系；错配为 owner、超级用户、其他清理或业务角色一律拒绝。
对不带 RLS 的共享表，列级 GRANT 不能限制角色只删到期行；这一边界必须如实记录，不能宣称数据库已强制执行 TTL。

### 3.3 批次、并发与媒体组

复用单二进制、已有清理模块的执行形状，增加一次性 `tgm cleanup-shared` 管理命令；
不新增常驻服务、HTTP 接口、队列框架，不把专用凭据交给 fanout。
批量上限、批间等待与频率沿用 `spec/04`，cutoff 取数据库时间，按时间与完整主键排序。

每批要求：

1. 事务级作业锁避免同类清理重叠；批间释放，不持事务跨外部 I/O。
2. 先处理可删除的聚合事件，再回收已释放组关系的成员和普通事件；
   未扇出的组、直接引用、间接组引用都保留。新到达成员与聚合继续使用既有媒体组锁键，
   清理加入相同协议；锁后另起语句复查，不复用等待前的候选快照。
3. 所有共享写路径按一致顺序取锁，检查采集的两种插入入口、聚合、扇出标记、job 认领和完成，
   不只修清理函数。用外键保护并发新投影与新成员绑定；不新增平台级全局写锁阻塞正常扇出。
4. `DOWNLOADING` 尚在有效回收期限内的 job 保留。过期下载与重新认领的竞态必须以锁后新语句复查，
   不能用旧 `next_retry_at` 删除已刷新 job。清理先提交时，迟到完成必须回滚档案写入并沿用现有对象补偿删除路径；
   若无法证明该路径安全，本片停止在测试失败处升级，不能长期跳过全部过期 job 来制造假完成。
5. 单批实际删除的原始事件不超过既有上限；级联只释放组关系与 job，不级联租户投影。
   平台日志的 `rows` 明确只计本批原始事件，不冒充级联行数。
6. 删除与日志同事务提交。日志失败、约束竞态或 SIGTERM 取消当前未提交批次；
   已提交批次不撤销，重跑从数据库继续，无额外执行状态表。

该协议按 READ COMMITTED 验证；拒绝会复用旧事务快照的隔离级别，不只在文档中假定连接配置正确。
调度增加独立 systemd service/timer 样例。命令可运行、样例正确与生产确已启用调度分开验收。
