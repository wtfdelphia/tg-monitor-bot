# 修复 5f6f41a 深度审核问题

## 任务

修复对提交 `5f6f41a5e021a9876b1f0bb583744a19966c96d4` 深度审核确认的
驱动循环、卡口信任根、数据库权限、宿主凭据、进程边界、日志写入和状态账本问题。

本次改动命中 `AGENTS.md` §五 的安全面、卡口与发布边界，必须先由人审核本提案；
在提案获准前，不直接修改驱动实现。

## 已确认问题

### P0

1. `run_gates` 将 `TGM_DB_URL_OWNER` 注入任务 worktree 执行的
   `cargo test`、`cargo run` 与审计脚本，任务代码可借高权限连接读写数据库。
2. 执行器环境重新注入宿主 `HOME` 与宿主 `PATH`，可读取宿主 SSH、GitHub、云厂商、
   Docker、Cargo 和其他用户配置凭据。
3. watchdog 只终止原进程组，执行器可以通过 `setsid` 脱离，超时后继续修改 worktree、
   主仓或状态账本。
4. Git 默认接受 `refs/replace/*`。执行器可替换固定 `BASE_COMMIT` 对象，绕过保护路径、
   helper 完整性与 `diff-tree` 检查。

### P1

1. 基线缺少 `ai-gates.sh` 时，驱动直接信任当前 `HEAD` 作为 bootstrap 卡口脚本来源，
   没有独立信任锚。
2. 推送后最后一次基线检查与 `gh pr create` 之间存在 TOCTOU，PR 的实际 base 可能已漂移。
3. `--no-pr` 推送成功后仍把任务写成 `done`，状态不代表已进入人工合并流程。
4. 执行器继承驱动锁 fd 9，可以主动 `flock -u 9` 释放单实例锁并制造并发竞态。
5. `logs/` 被保护检查整体豁免，日志目录或日志文件符号链接可导致驱动重定向覆盖其他路径。
6. `ai-gates.sh --no-db --from migrate` 会跳过全部数据库卡口，却返回“全部卡口通过”。

### P2

1. `state_fingerprint` 不包含状态账本根目录自身的类型、权限和属主变化。
2. `protected_tree_mismatches` 不检查保护目录自身的权限、属主和可遍历性变化。

## 修复方案

### 1. 固定不可替换的 Git 信任根

- 所有 `git show`、`cat-file`、`ls-tree`、`diff-tree`、`rev-list` 与 helper 校验命令
  在驱动和卡口中统一设置 `GIT_NO_REPLACE_OBJECTS=1`。
- 启动时扫描并拒绝 `refs/replace/*`、影响对象解释的其他可变 Git 引用和异常对象环境；
  相关引用与配置变化纳入 Git 守卫指纹。
- 删除当前 `HEAD` 无条件 bootstrap。基线没有可信卡口脚本时直接 `blocked`，或只允许
  由仓库外人工配置的固定 SHA/blob 摘要进行 bootstrap。

### 2. 拆分任务代码与高权限卡口

- `cargo fmt`、`clippy`、离线构建和任务测试只使用受限测试连接或无数据库环境，
  不向任务代码注入 `TGM_DB_URL_OWNER`。
- 迁移、RLS 审计、双遍破坏测试改为驱动侧固定可信入口；高权限连接只进入固定的、
  不受任务 worktree 控制的脚本或二进制，不进入任务编译产物、测试代码或可修改 helper。
- 为 `sqlx::test` 单独建立可创建临时测试库但无 owner/superuser 能力的测试角色，
  并验证该角色不能读写生产数据库对象；需要高权限的测试前置动作由受控外部阶段完成。
- 为卡口增加反向测试：恶意测试代码尝试读取 owner 连接、执行 `ALTER ROLE`、读取其他
  租户或修改生产表时必须失败。

### 3. 收紧执行器宿主隔离与终止边界

- 执行器使用专用临时 `HOME`、`XDG_CONFIG_HOME`、`CARGO_HOME` 和固定系统 `PATH`，
  不继承宿主用户目录或用户可写路径。
- 执行器放入独立 cgroup/systemd scope 或等效容器边界；超时时终止整个 cgroup，确认
  cgroup 为空后才运行保护检查、卡口和状态结算。
- 启动包装器显式关闭驱动 fd 9 及其他内部 fd，并加入 close-on-exec 复核，防止执行器
  释放 `flock`。
- 保留 SSH、Git 凭据和 GitHub 配置的最小注入；执行器不能读取宿主凭据目录。

### 4. 收紧日志、状态和目录守卫

- 将运行日志迁移到 Git common dir 外的驱动专用目录，使用安全创建方式并拒绝符号链接；
  不再对主仓 `scripts/ai-driver/logs/` 做整体豁免。
- `state_fingerprint` 纳入状态根目录自身的类型、权限、属主、真实路径和链接状态；
  `check_state_dir` 同时执行权限与属主校验。
- 保护目录纳入权限、属主和可遍历性检查；`find`、`stat`、读取或比较失败必须
  fail-closed，不得把错误当成空结果。

### 5. 修复出口和参数假绿

- `--no-pr` 不得产生 `done`；改为 `blocked` 或新增明确的 `pushed` 状态，并在文档中
  固定其语义。
- `--no-db` 与从数据库卡口开始的 `--from` 组合直接拒绝；任何跳过必需卡口的运行都
  返回非零，不得输出“全部卡口通过”。
- 推送后创建 PR 后，读取 PR 的实际 base SHA 并与启动时 `BASE_COMMIT` 比较；不一致时
  标记 `blocked`，不得写入 `done`。
- 补充远端分支保护前提和基线漂移的竞态测试，覆盖推送、创建 PR、状态写入之间的中断。
