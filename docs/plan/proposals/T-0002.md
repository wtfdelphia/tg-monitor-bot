# T-0002：扫码登录状态机升级提案

## 已落地部分

纯状态迁移已落在 `crates/tg/src/qr.rs`，没有接触网络、Telegram 凭据或数据库。
覆盖内容包括：

- `auth.loginToken` 对应的等待扫码状态；
- `loginTokenMigrateTo` 对应的 DC 迁移状态；
- `loginTokenSuccess` 的普通登录与 2FA 分支；
- token 过期、二维码刷新、旧 token 拒绝和主动取消；
- `rstest` 表驱动的 L1 迁移与失败分支测试。

本轮又完成了不依赖账号凭据的接入基础：

- workspace 锁定 `grammers-client 0.10.0`；
- `glass_pumpkin` 精确固定为 `2.0.0-rc0`，修复 `rc1` 与 `num-bigint` 的编译冲突；
- `crates/tg/src/client.rs` 提供 MTProto 客户端、更新流、内存 session 同步和优雅关闭；
- 无凭据 MTProto Ping 已成功，`tgm-tg` 的 17 项测试通过。

这部分不等于 QR 首发能力已经验收。`docs/design/plan/00-里程碑与工期.md` §4.3
要求的 WP-2 出口仍包含真实设备上的 QR 全分支实测。

## 必须升级的实测项

`docs/design/spec/08-账号接入.md` §3.5 的六项实测仍需由具备测试账号、手机确认能力
和可回收凭据的人员执行：

1. 同 DC 正常扫码登录；
2. 非默认 DC 账号触发并完成 `MigrateTo`；
3. 开启 2FA 的账号完成密码校验；
4. token 过期后刷新二维码，并证明旧 token 不可用；
5. session 落库后重启进程仍保持授权；
6. 手机端取消授权后检测 `unauthorized` 并更新 `identities.status`。

执行记录应逐项回填结果、时间、测试账号范围和失败处置；没有真实证据的项目保持未
通过，不用纯状态机测试替代真机结论。

## grammers 核对

当前依赖与最小连通性核对已完成：`grammers-client 0.10.0` 已锁定，且将
`glass_pumpkin` 固定为 `2.0.0-rc0`，否则会在当前依赖解析结果下出现 `num-bigint`
类型不兼容。无凭据 MTProto Ping 已成功，说明 Rust 依赖、SenderPool 和网络握手路径可用。

这仍不替代授权账号验证。`invoke_in_dc`、真实 `MigrateTo`、QR 登录、session 加密落库、
消息更新接收、断线恢复和重启恢复仍需用可回收测试账号完成。

核对完成前不得把“文档中已核对”写成“当前代码已验证”。
