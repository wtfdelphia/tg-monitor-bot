# PRE-013：目标机验收下载韧性与代理回退

任务 id：`PRE-013-native-target-download-resilience`。

本提案只改进非生产目标机验收脚本在代理、GitHub Release 限流和网络抖动下的取包能力；不改变候选包格式、签名身份、来源证明、安装隔离、systemd 安全预检或生产边界。

## 一、背景

目标机验收脚本原先只使用 GitHub Release 直链下载。目标机处于 HTTPS 代理、出口限流或 GitHub 直链不稳定的网络环境时，下载阶段可能在验签前失败，无法区分网络传输失败与候选材料本身无效。

维护人提供的新脚本已在候选 `candidate-42464415302-a1-cd464213914c` 上完成一次 Rocky 9 验收：代理透传下候选材料下载、签名、provenance、二进制预检、隔离安装和六角色非生产运行时验收均通过。该结果是实现参考和目标机证据，不等于脚本改动已经进入 `dev`。

## 二、拟实施改动

### 1. 下载来源回退

为 `scripts/tgm-native-target-acceptance.sh` 增加可配置下载来源：

- `direct`：GitHub Release `releases/download` 直链；
- `api`：GitHub API 获取 Release 元数据和资产 id，再获取一次性资产下载地址；
- `gh`：已登录的 `gh release download`；
- `auto`：按直链、API、`gh` 顺序回退。

API 请求不跟随跳转；API 返回的一次性下载地址必须是 HTTPS，正文下载不携带 API 认证头。每个文件仍以临时文件下载，拒绝覆盖已有材料，成功后再原子落盘。

### 2. 代理和限流

- 沿用 `https_proxy`/`HTTPS_PROXY`/`all_proxy`/`ALL_PROXY`，日志只显示脱敏后的代理地址；
- 每个文件支持有限次数的来源回退和轮次重试，默认值可通过环境变量覆盖；
- 保留连接超时、低速检测和旧版 curl 兼容，不依赖 CentOS 7 的 `--retry-all-errors`；
- Rocky 模式检查 Docker daemon 是否配置独立代理，只告警，不把 shell 代理误认为 Docker daemon 代理。

### 3. GitHub API 认证

Token 读取顺序固定为 `TGM_GITHUB_TOKEN`、`GITHUB_TOKEN`、`GH_TOKEN`，可选读取已登录 `gh` 的 token。Token 只写入权限为 `0600` 的临时 curl 配置，不放入进程参数、不回显、不随 API 跳转外发；`gh` 路径由 `gh` 自身处理认证。

### 4. 材料复用

增加 `--reuse-materials`，只复用当前用户拥有的非空普通文件，不覆盖已有材料；复用材料仍必须通过 cosign、SHA-256、provenance、包内 BUILDINFO/SBOM 和二进制检查。`--no-download` 与 `--reuse-materials` 互斥。

## 三、验收判据

1. Bash 语法、参数边界和静态安全检查通过；旧版 curl、Python 3.6 兼容路径保持可用。
2. 直链、API、`gh` 三条下载路径能在模拟网络失败/限流时按配置回退；最终材料只能通过临时文件原子落盘。
3. API 认证头不随跳转发送；非 HTTPS 资产跳转、错误 Release 元数据、重复或异常资产、大小不一致均拒绝。
4. 代理地址和 Token 不出现在正常日志、命令参数或候选材料目录；失败时保留诊断目录但不保留明文 Token 配置。
5. 已有签名、provenance、SHA-256、候选来源、二进制、安装隔离和 CentOS 7 fail-closed 语义不变。
6. 在当前 `dev` 产生的新候选包上，至少完成 Rocky 9 六角色非生产验收；生产服务、生产 timer、真实租户和正式发布均不触碰。
7. 目标机脚本说明同步更新，明确 Docker daemon 代理与 shell 下载代理是两个独立配置面。

## 四、边界与风险

- 不修改 `.github/workflows/binary-candidate.yml`、正式发布 workflow 或候选签名策略。
- 不把代理可达性当作签名可信度；所有下载结果仍必须完成完整材料验证。
- 不支持通过跳过验证、关闭 TLS、`--insecure-*`、放宽 systemd 预检或 `seccomp=unconfined` 解决问题。
- `gh auth token` 和环境 Token 属于目标机敏感输入；脚本只在 GitHub API 主机使用，退出清理临时认证配置。
- Rocky 验收所需 PostgreSQL、Redis、MinIO 镜像拉取仍依赖 Docker daemon 的网络配置，不能由 shell 代理自动解决。
