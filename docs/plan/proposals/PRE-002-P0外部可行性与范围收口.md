# PRE-002：P0 外部可行性与范围收口

## 当前状态

本提案承接 `docs/plan/编码实施前置待办.md` 的 P0 项，不直接实现需要真实 Telegram
设备、真实凭据、外部平台配置或产品决策的事项。

当前核对基线为 `32e49103ac87f2ae10f14a1fd2d6b73a954ff8ad`。产品负责人已经确认
**首发包含媒体**；Telegram 真机测试条件和非平台自有目标租户账号已经具备。尚未完成的
不是条件准备，而是受控执行入口、真实验证记录，以及对受保护设计文档的受控同步。

当前代码已经落地租约 repo 和 QR 纯状态机，但以下事实仍不能由本地单元测试推出：

- grammers 的真实 MTProto 连接、消息更新、session 恢复和断线恢复；
- QR 登录同 DC、DC 迁移、2FA、过期刷新、取消授权和 session 重启恢复；
- Telegram Login 的 BotFather 配置、Allowed URLs、OIDC 回调、JWKS 换钥与失败路径；
- 目标租户申请并持有自己的 `api_id/api_hash` 的流程、限制和失败形态；
- 首发包含媒体中转；该决定对套餐、规格和验收的同步尚未完成。

## 需要完成的工作

### 1. 首发媒体范围同步

产品负责人已选择“首发包含媒体”。受控同步必须写明：

- 首发能力与明确不做的能力；
- 套餐和容量口径是否变化；
- `spec/01`、`spec/02`、`eng/02`、任务卡和首发验收如何同步；
- 媒体失败时的处置，不再默认降级成“首发只转文本”。

决策已经完成，但在文档同步和媒体验收完成前，不把当前 MinIO 容器存在写成媒体能力
已完成。触及需求基线或 `plan/00` 的变更仍按 A 类变更控制执行。

### 2. grammers 与 QR 真机验证

沿用 `T-0002` 与 `docs/plan/proposals/T-0002.md`，使用测试账号和可撤销凭据完成：

- 同 DC 扫码；
- `MigrateTo` / 非默认 DC；
- 2FA；
- token 过期刷新并拒绝旧 token；
- session 落库后重启恢复；
- 手机端取消授权后识别为 `unauthorized`。

每项记录时间、账号素材标识、结果、失败处置和证据位置；不把手机号、二维码 token、
`api_hash`、session 或密码写入仓库。

条件已具备，但当前仓库仍只有客户端边界和纯状态机，尚无覆盖授权、session 加密持久化、
重启恢复和断线恢复的完整测试 harness。先完成入口，再按
`docs/plan/evidence/P0-外部验证手册-2026-10-08.md` §二执行。

### 3. 控制台登录可行性

先准备专用 BotFather 配置、Client ID/Secret 和可访问的 HTTPS 地址；当前仓库环境可用于
准备，但不能直接完成真实回调，因为 `crates/app/` 仍是骨架，`tgm serve --role
control-plane` 尚未提供 HTTP endpoint。待 control-plane callback 实现并完成安全注入后，
用专用配置完成一次真实流程：

- 登记实际站点 origin 与回调 URI；
- 验证本地开发地址、预发地址和正式地址的可用性边界；
- 完成 Authorization Code + PKCE 回调与会话签发；
- 验证未知 `kid`、JWKS 拉取失败、换钥期间新旧 key 并存和过期 token；
- 确认控制台二维码与 MTProto 账号二维码的页面标题、说明和错误态不混淆。

失败时统一拒绝登录，不把未知 key、回调不匹配或过期 token 降级为未验证用户。

### 4. 租户自带 `api_id` 验证

使用已具备的非平台自有目标租户账号，按官方申请入口完成一次申请记录，并只保存：

- 申请步骤是否可完成；
- 需要的账号条件与限制；
- 失败页面或失败类别；
- 是否支持租户自带归属模式；
- 不保存 `api_hash`、手机号、验证码或任何 session 材料。

Telegram 官方资料确认申请入口是 `my.telegram.org` → `API development tools`，
并要求应用使用自己的 `api_id`；这只能作为设计输入，不能替代本项目目标租户的实际
申请记录。

### 5. G0/G1/G2 证据归档

把以上结果写入一次性关口记录，至少包含：

- 结论：通过、未通过、部分通过或不适用；
- 证据载体与复跑入口；
- 未通过时的失败处置；
- 对 `spec/00`、`spec/01`、`spec/07`、`spec/08`、`plan/00` 和风险登记的影响；
- 对应 WP-1/WP-2/WP-5/WP-6 出口是否可以转绿。
