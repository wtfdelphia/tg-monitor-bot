## 一、基线与核查结果

基线为 PR #54 合入后的 `dev`：`1562ca0be16f1a522b16e7861a21cae33099cb40`。
PR CI run `40315117833`、合并后 push CI run `40316415986` 均已成功；后者的
`static`、`database` 均通过。该结果只属于前片，不代替本片将来的门禁。
前片证据见 `../evidence/WP-8-共享原始事件回收-2026-10-26.md`。

复用阶梯核查结论：这项需要做，否则规格中的未命中短 TTL 仍无法兑现；已有租户投影清理和
共享事件清理覆盖了批量、角色、日志与取消，不需要再造清理框架。

已核查采集落库、媒体组聚合、扇出、规则处理、入队及两类清理的共用入口：

- `enqueue_delivery_tasks` 在任务写入事务中更新 `tenant_events.processed_at/matched`，
  并将命中结果累积到原始事件及媒体组成员的 `matched_any`。默认 `matched = FALSE`
  或全局 `matched_any = FALSE` 都不能单独证明规则处理已结束。
- 当前 `cleanup-tenant --category tenant-events` 按套餐期限删除投影，只保护在途任务；
  新短 TTL 不得照搬这个条件，否则终态任务也会被提前脱钩。
- `cleanup-shared` 保护所有投影和成员引用。因此已处理、未命中且没有任务的投影，
  仍会阻止原始事件按未命中期限回收。
- `fanout_canonical_event` 持共享身份锁，但尚未持租户事件生命周期锁，插入也没有以
  `fanned_out` 阻止已完成扇出的事件再次生成投影。提前清理会使旧的重放路径重新产生未处理行。
- 规则处理在入队事务外读取事件与规则。共用入队入口目前没有在锁后以处理终态拒绝旧计划，
  事件消失也会返回数据库错误或 `NotFound`；不能让合法清理变成后台处理循环退出。

## 二、请求定案的留存语义

建议新增“已处理未命中投影”的短期留存例外，而不是延长未命中原始事件 TTL，
也不是恢复 `canonical_events` 到租户投影的危险级联。

短 TTL 投影必须同时满足：

1. 当前租户归属正确，`processed_at IS NOT NULL` 且 `matched = FALSE`；
2. 原始事件已完成扇出，且 `canonical_events.created_at` 严格早于数据库 cutoff 减去
   `spec/04` §一规定的未命中期限；不改用 `processed_at` 或投影时间重新起算；
3. 没有任何状态的 `delivery_tasks` 引用。即使状态为 DONE、DEAD 或 CANCELLED 也保留，
   不借本片提前脱钩任务，不缩短日志或冻结 payload 的期限。

该例外按每个租户的处理结果判定，不以其他租户的命中结果决定本租户未命中投影的存活。
另一租户仍未处理、已命中或存在任务时，其投影和任务不受影响；共享原始事件仍须通过现有全局引用检查。
原始事件命中过任何租户时，继续走既有命中留存规则，不因另一租户投影被删除而重置 `matched_any`。

其余投影沿用既有套餐留存规则。本片不调整已有套餐清理的未处理事件政策；
但新的短 TTL 路径必须保护所有未处理投影，不能把积压当未命中提前删除。
媒体组必须保留既有组先于成员的回收次序：未扇出的组、仍有投影的组和有效下载继续受保护，
成员已标记扇出不代表它所属的聚合事件已完成处理。

这改变了 `spec/04` 中投影一律按套餐保留的表述，属于 `plan/00` §9.1 **A 类变更**。
获批后新增 ADR，说明它如何细化 ADR-0009/ADR-0015 及投影保留期；不改写旧 ADR 的决定和论据。
同时在规格中明确：未命中期限是可安全回收的年龄门槛，不是精确时刻硬删除承诺。
未完成处理、存量引用或有效下载可导致超期，必须报告滞留与失败，不能为满足时钟强删数据，
也不能将这些受保护记录计为已完成回收。小时级调度和生产是否已启用要分开验收。

替代方案不采用：

- 将共享事件统一保留到套餐期限：实现简单，但放弃未命中短 TTL，也延长正文存储时间。
- 直接级联删除所有投影：会删除未完成处理或其他租户的使用关系，绕开既有引用防线。
- 给投影另存正文或新增历史/墓碑表：扩大内容留存与迁移范围；先用扇出终态和共同锁阻止重建，
  本片不要求新的历史查询或回放能力。若现有字段无法证明安全，再升级，不临时加表。

## 三、复用路径与并发边界

建议在 `tgm cleanup-tenant --category` 增加 `unmatched-events`，复用 `tenant_cleanup`、
全部状态租户分页、事务级上下文、现有批量上限与批间等待、固定日志和取消机制。
短期清理与套餐事件/任务清理使用同一租户事件生命周期排他锁；不新增共享角色删除租户数据的权限。

需统一检查所有生产调用方，而不只修改清理 SQL：

- 扇出写入先持租户事件生命周期共享锁，再持既有身份共享锁；等待后用新语句复查父事件与扇出状态。
  完成扇出的原始事件允许返回已有投影，但不得创建新的投影；清理已删掉的投影不重建。
  未完成扇出的崩溃恢复仍可补齐缺失投影，正常采集的新事件不受影响。
- 规则入队沿用规则版本锁 → 租户事件生命周期共享锁 → 身份共享锁 → 事件行锁的方向。
  在锁后复查处理状态；并发旧计划不能把已经完成的未命中结果改成新任务。
  已有任务的幂等重放返回既有结果，不重复投递，也不因本片改变既有任务随机 id 或冻结 payload。
- 清理持生命周期排他锁后重新验证年龄、扇出、处理结果和全部任务引用，删除与日志同事务提交。
  锁等待后的判定要求 READ COMMITTED；不支持的隔离级别直接拒绝。
- 区分后台列表项被并发回收与真正的数据错误：合法回收不使内部处理循环退出，也不自动重建投影；
  不把所有 `NotFound`、SQL 错误或规则版本缺失一概吞成成功。共用函数的返回语义和全部调用方须有回归。
- 共享清理仍使用原有身份排他锁、媒体组锁和非延迟引用外键，不放宽无引用检查。
  用实际并发证明两类清理与扇出/入队没有反向锁顺序；发现无法证明的路径时停止并升级。

调度沿用现有 systemd 命令模板和小时入口，建立“短期投影清理完成后再共享回收”的显式依赖，
而不是假定两个 `hourly` timer 的启动先后。两个命令仍以各自系统用户和独立 Secret 文件运行，
不合并数据库身份或让一个进程同时读取两套凭据。前置失败不能把整轮报成成功；
手工重跑与生产未启用状态须明确记录。

## 四、权限、实现与文档范围

批准的增量范围如下：

- 追加迁移，不改已应用文件、不新增表或运行角色。
  为 `tenant_cleanup` 增加 `tenant_events` 的 `canonical_event_id`、`processed_at`、`matched`
  读取，以及 `canonical_events` 的 `id`、`created_at`、`fanned_out` 元数据读取。
  原始事件无 RLS，这些列授权是新的跨租户元数据边界，须明确登记；不授正文、媒体内容、凭据或原始事件写权限。
- 用单独 DELETE 策略约束短期投影删除，保留租户限定和无任何任务引用条件；
  读取策略须允许查询需要判断的候选元数据，不能因旧到期策略隐藏记录而得到假空集。
  不为短期清理放宽终态任务脱钩权限，不新增共享清理角色的租户详情权限。
- `crates/db/src/tenant_retention.rs`、`crates/app/src/tenant_retention.rs`、CLI 与 systemd 样例：
  固定类别、事务复查、批量、退出和小时清理的依赖顺序。
- `crates/db/src/repo.rs`、`crates/app/src/pipeline.rs` 及其调用方：扇出重放和处理终态的共同保护。
- `crates/db/src/audit/queries.sql`、`scripts/audit-double-pass.sh`、`eng/04`：同步 `C9` 精确权限白名单及反证；
  既有共享角色、引用约束审计与双遍不得削弱。`ci.yml` 原则上不改，继续使用现有裁决链路。
- db/app/CLI 测试、SQLx 元数据、必要的索引、配置和部署说明；新增 ADR 后同步
  `spec/02`、`spec/04`、`spec/05` 的已批准语义，补测试策略、实施证据与计划登记。

不处理通知终态期限、租户注销、同意凭证、举报入口及媒体清理旧日志债务；
不读取真实 Telegram/AWS 凭据，不连接生产库，不新增依赖或通用调度框架。

## 五、验收与批准边界

获批后必须留下可复跑检查：

- 年龄边界之前、恰好相等、之后；数据库时间与投影/处理时间不一致；未处理默认未命中不能被新类别删除。
- free/pro、全部租户状态；一租户未命中、另一租户未处理或已命中；同一原始事件全部已处理未命中且无任务时，
  先删投影再经共享命令删除原始事件，不能只测无投影的旧场景。
- 每种任务状态均阻止短期投影删除；投递日志、冻结 payload、重试和原有套餐清理语义不变。
- 媒体组的未扇出、未处理、成员间接引用、命中传播、有效下载及组后成员的最终回收。
- 两个真实连接观察锁等待，覆盖处理/入队先提交与清理先提交、旧计划再次入队、扇出先提交与清理先提交、
  扇出崩溃重跑、投影清理与共享回收同时运行。去掉共享锁、终态复查或扇出保护时，对应用例必须变红。
- 真实 `tenant_cleanup` 连接下验证最小列权限、RLS、无 GUC 与错租户拒绝、正文和凭据不可读写；
  超授列、放宽删除条件或遗漏任务状态时，对应审计或行为反证失败。
- 限批、多批、批间释放锁、重叠运行、日志失败回滚、SIGTERM 中断与重跑；
  小时调度的两个独立身份确实按依赖顺序执行，前置失败和未处理积压如实报告，不假报 TTL 已满足。
- 生产路径迁移、迁移重入、SQLx 在线 prepare/check、完整 `scripts/ai-driver/ai-gates.sh` 与审计双遍通过；
  回归事件、规则版本、pipeline、投递、中转和两类既有留存链路，最终由本片 PR CI 裁决。

构建与验收结束后检查磁盘和任务独占 target，定向清理可丢弃缓存及临时 Docker/systemd 残留；
不删除源码、`.sqlx/`、证据、正在使用的 Compose 栈或具名卷。
