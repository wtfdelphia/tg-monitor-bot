## 一、为什么不能直接复用现有列

`identities.target_probe_not_before` 已用于目标自检的发送身份认领节流和 Bot API 429 冷却，
由 `crates/db/src/target_probe.rs` 读取、设置与推进。虽然 `docs/design/spec/03-数据模型.md`
将它概括为发送身份的执行保留与 429 冷却，但列名、调用方和现有状态机都属于目标自检。

将 MTProto 投递收到的 `FLOOD_WAIT` 截止时间也写入该列，会令目标自检和投递互相延长冷却；
到期恢复、人工 `reset-status`、目标探测成功/失败的写入都可能改变投递调度依据。复用还会
让两个独立外部 API 的限流原因无法区分，难以验证某个状态变化是否越过 Telegram 服务器给出的等待。
因此建议新增专用 `identities.flood_wait_until`，不修改 `target_probe_not_before` 的语义。

## 二、拟实施变更

1. 新增只增、幂等迁移，为 `identities` 增加
   `flood_wait_until TIMESTAMPTZ NOT NULL DEFAULT '-infinity'`，不改写任何已应用迁移。
2. 只给 `app_user` 该列的列级 `UPDATE` 权限，不授予 `identities` 表级 `UPDATE`，不扩大其他
   角色权限。迁移顺序、重跑快照和撤销状态须按本地迁移纪律验证。
3. 在 `record_delivery_failure` 的现有事务里，只有任务错误码为 `FLOOD_WAIT` 且发送身份仍为
   `bot`、状态不是 `unauthorized`/`banned` 时，原子写入任务退避、身份 `flood_wait`、截止时间
   和脱敏审计；身份截止时间取已有截止时间与新任务 `next_retry_at` 的较晚值，不能缩短已存在冷却。
   更新任务、身份或审计任一失败时整笔事务回滚。
4. 在任务领取入口阻止处于有效 `flood_wait_until` 的 Bot 领取任何任务；到期时在同一租户事务
   内将该 Bot 从 `flood_wait` 自动恢复为 `offline` 并写恢复审计，再允许其继续使用已存 session。
   该恢复只作用于 `kind='bot'`、`status='flood_wait'` 且截止时间已过的租户身份。
5. 发送身份候选查询排除仍在冷却的 Bot；候选发现与任务领取均执行到期恢复，以覆盖正在运行的
   sender loop 和重新发现的 sender。`unauthorized`、`banned` 永不由该路径恢复。
6. 手动 `reset-status` 不得清除或绕过未到期的 Bot 冷却；过期冷却仍可按现有手动操作规则处理，
   但正常发送路径不依赖人工复位。
7. 身份列表和 dashboard 对有效/过期冷却显示一致；dashboard 的 `flood_wait_until` 同时反映
   任务级重试与身份级冷却，且不返回 token、session 或 Telegram 错误正文。
8. 更新 `C2`/相关数据库断言，使 `app_user` 的新列授权成为明确、最小且可反证的权限集合；
   更新审计 SQL、自检脚本和角色权限测试。不得通过放宽既有审计断言或跳过 double-pass 来过关。

## 三、验收判据

- `record_delivery_failure(FLOOD_WAIT)` 的隔离 DB 测试证明任务、身份截止时间、身份状态与审计原子提交；制造写入失败时四者全部回滚。
- 有效冷却期内，同一 Bot 的新任务与失败任务均不能被领取；受限 `app_user` 运行，其他 Bot、租户和目标探测状态不受影响。
- 冷却到期后自动恢复一次为 `offline`，同一任务可重领；恢复前不能投递，恢复后使用现存 session，重复扫描不重复恢复或重复发送。
- `unauthorized`、`banned` 即使截止时间已过也保持原状态；手动复位不能提前缩短有效冷却。
- dashboard 与身份列表对身份冷却一致，错误正文、Token 与 session 不泄漏。
- 列权限反证证明新增授权仅限 `app_user` 的指定列；撤销/破坏必须命中对应审计断言，恢复后目录快照逐字节一致。
- `scripts/migrate-idempotent.sh`、完整 `scripts/ai-driver/ai-gates.sh` 与相应 DB/app 测试通过；真实 Telegram 用例仅在全部非生产状态机测试通过后由维护人手动运行。

凭据处理或 CI 工作流；若测试发现必须触碰这些范围，先停止并补充提案。不会使用生产凭据、
连接生产数据库、安装生产服务或自动制造 Telegram 限流。
