## 二、正式业务实现前置项

### 1. 统一租约获取、续租和释放语义（已完成）

当前任务卡与规格原先存在直接冲突，现已统一为：

- `acquire` 首次从 1 开始，同 worker 重复获取不改变 token，过期接管递增 token；
- `renew` 必须匹配当前 worker 与 token，过期租约不得复活；
- `release` 只让租约立即过期并保留行，确保 token 不回退。

对应实现和测试已落在 `crates/db/src/repo.rs` 与 `crates/db/tests/lease.rs`，
任务卡 `T-0001` 已归档为 `done`。

验收判据：任务卡、账号接入规格和测试用例使用同一套 token 语义；并发抢占只能成功
一次，正常续租不产生不必要的 token 变化，旧 worker 不能继续续租或写入。

- `docs/plan/backlog/T-0001-租约repo层与抢占测试.md`

## 六、建议执行顺序

建议按以下优先级推进未完成事项：

1. **G0–G2：完成基线核对与责任方冻结。** 项目内迁移复核材料已获用户批准；仍由相应产品/工程
   责任方确认 SRS、SDD/TS 冻结记录与未验项处置，不将材料批准写成关口通过。
2. **G1：补齐外部输入。** 只安排真实 OIDC provider 联调和目标租户自办 `api_id` 申请的
   脱敏记录；已有 QR 证据不重跑，同 DC 子项不写成已通过。
3. **WP-2/WP-6：只补未决外部边界。** 不重跑已有 QR/session 证据；等待真实 OIDC provider
   与目标租户自办 `api_id` 记录。生产 KEK、周期授权复核和其余出口按各自记录跟踪。
4. **WP-8：收集外部决策输入。** 使用 `WP-8-外部决策输入收集-2026-11-13.md` 由产品、法务、
   运维责任方提供批准文本、实际存储配置和生产验收条件；输入到位前不改策略、不启用 timer。
5. **G3/G4：按收口矩阵逐项处理未完成出口。** 保持 G4 FloodWait `partial/not-run`，只接受
   安全、自然出现的事件，不重复探针、不加压、不主动制造限流。
6. **G5/G6：等待生产环境决策后推进。** 真实恢复、RPO/RTO、容量、告警与值班须由责任方
   提供环境和批准；多实例混沌仍由单实例决策约束，未启用多实例前不包装为首发阻塞。

已有实现期代码和真机证据以各自 WP 记录为准；它们不替代真实 OIDC provider、目标租户
`api_id` 申请或正式基线冻结。
