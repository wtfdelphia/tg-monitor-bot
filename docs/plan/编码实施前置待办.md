## 二、正式业务实现前置项

### 1. 统一租约获取、续租和释放语义（已完成）

当前任务卡与规格原先存在直接冲突，现已统一为：

- `acquire` 首次从 1 开始，同 worker 重复获取不改变 token，过期接管递增 token；
- `renew` 必须匹配当前 worker 与 token，过期租约不得复活；
- `release` 只让租约立即过期并保留行，确保 token 不回退。

对应实现和测试已落在 `crates/db/src/repo.rs` 与 `crates/db/tests/lease.rs`，
任务卡 `T-0001` 已归档为 `done`。

验收判据：任务卡、账号接入规格和测试用例使用同一套 token 语义；并发抢占只能成功
一次，正常续租不产生不必要的 token 变化，旧 worker 不能继续续租或写入。

依据：

- `docs/plan/backlog/T-0001-租约repo层与抢占测试.md`
- `docs/design/spec/08-账号接入.md` §4.2–§4.3

## 三、启用 AI 自动编码驱动前置项

### 8. 将驱动版本进入可信远端基线

当前本地提交为 `57c602a...`，远端 `dev` 仍停留在较早提交，缺少本次驱动脚本所需的
可信卡口基线。`ai-run.sh` 会拒绝在任务基线缺少可信 `ai-gates.sh` 时运行，这是保护
行为，不应绕过。

验收判据：按人工发布流程将驱动版本进入远端基线，并取得该版本对应的 CI 结果。

依据：`scripts/ai-driver/ai-run.sh` 的可信卡口基线检查。

### 9. 解决 GitHub CLI 兼容性

当前本机 `gh` 版本为 2.4.0，而驱动使用的 PR 核验字段包括 `baseRefOid` 和
`headRefOid`。本机版本不支持这些字段，可能导致 PR 创建成功后核验失败。

需要升级 `gh` 或改用当前版本支持的查询方式，并验证：

- PR 创建成功；
- base 分支名和 base SHA 正确；
- head SHA 正确；
- 查询失败时任务不会误记为完成。

依据：`scripts/ai-driver/ai-run.sh` 的 `push_and_pr`。

### 10. 明确自动执行权限与发布保护

当前驱动使用同一用户下的全权限执行器。临时 `HOME`、环境白名单和 systemd cgroup
只能减少环境泄入，不能构成文件系统沙箱或完整宿主隔离。

在启用无人值守前需要明确：

- 允许哪些远端分支写入；
- 哪些 CI 检查是合并必需项；
- 执行器使用何种凭据；
- 是否接受同一用户全权限执行器的信任边界；
- 是否需要专用用户、容器或其他隔离边界。

验收判据：完成一次受控的创建分支、运行卡口、创建 PR、核验 base/head、失败回收和
状态结算演练。

依据：

- `scripts/ai-driver/README.md` 的环境边界说明
- `scripts/ai-driver/ai-run.sh` 的 `run_executor`、`run_gates`、`push_and_pr`
- 仓库根 `AGENTS.md` §七

   接入、QR 六项真机验证、控制台登录和租户自带 `api_id` 的可行性验证。

4. **P1：完成首发业务链路。** 在 P0 外部结论收口后，继续实现 Telegram 真实接入、
   session 加密落库、身份状态流转和控制台调用方。

P0 的真实设备和外部依赖验证。
