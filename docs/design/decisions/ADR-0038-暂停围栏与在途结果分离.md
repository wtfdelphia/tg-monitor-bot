# ADR-0038：暂停围栏与在途结果分离

状态：2026-10-27 维护人批准 `WP-8-tenant-lifecycle-stop` 后实施。

## 背景

停止后台发现不能停止已运行 worker，过期租约也不能证明网络连接已经关闭。
Telegram 发送与 PostgreSQL 提交不属于同一事务；不能承诺暂停提交后 Telegram 绝对不再收到任何请求。

## 决定

每租户生命周期锁先于规则、事件、共享回收和行锁。业务写事务及外部执行准入取共享锁，
暂停和恢复取排他锁；拿锁后用新语句在 READ COMMITTED 下复查状态。
暂停保留凭据、拒绝新业务写入和执行准入，允许只读查看及撤销自己的 Web 会话；deleted 不允许业务读写。

获准的外部请求算在途，即使实际发送晚于暂停提交。Telegram/KMS 等待期间不持数据库事务锁。
请求和长期 worker 用直连 `app_user` 的空闲连接标记存活，在 `application_name` 中只记录租户 id；
运维角色通过当前库的 `pg_stat_activity` 核对。普通业务池仍可走 PgBouncer，在线标记不得走 transaction pooling。
生产显式配置 `TGM_DB_URL_EXECUTION`；开发和受限测试可复用直连业务连接参数。

排空同时要求无 PENDING/FAILED/SENDING 任务、无未过期自有租约、无在线执行标记。
取消只碰尚未开始的任务，成功回执仍记 DONE；暂停后的确定失败转 CANCELLED 且不重试。
网络结果不确定、没有返回消息或分段已部分发送时保留 SENDING，日志保留原因，阻止排空和恢复。
不得把它伪写成“未发送”；待核对真实结果后另行处置。多步媒体和目标探测每一步重新准入。

暂停时间独立存储；存量 suspended 从首次迁移保守起算，不猜旧时间。
暂停命令分批过期租约和取消任务，保留 fencing 历史；恢复只允许已排空 suspended，旧任务不复活。
本片不自动进入 deleted、不销毁凭据、不做物理删除。

## 代价

每个在途执行需要额外直连，连接数需纳入容量预算。网络故障时连接可晚于进程退出被数据库识别，
此时宁可报告未排空。数据库宕机或重启会失去在线标记；运维必须先停止并确认旧进程退出，再恢复服务，
不能把重启后的空目录当作旧网络请求已结束的证据。

升级须停旧 worker 后迁移并重启全部新版组件，不保证旧版绕过新入口时仍受应用围栏保护。
凭据及消息内容不进入执行标记、固定审计或清理日志。
