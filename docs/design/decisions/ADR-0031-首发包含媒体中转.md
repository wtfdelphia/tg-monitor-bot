# ADR-0031：首发包含媒体中转

状态：**已定案**（2026-10-08）

## 决定

首发范围包含媒体消息处理和跨身份媒体中转。这里的“包含媒体”沿用现有产品与套餐边界，
不改变 free 档不提供 MTProto 和媒体中转的约定；pro 档继续使用现有单文件限制。

首发媒体链路按现有设计实现：媒体组聚合、跨身份流式下载与上传、下载过程中计算
`content_hash`、对象存储短期保留，以及跨身份投递所需的清理和失败重试。

媒体可行性验证失败时，不自动把首发改成“只转文本”；必须按 `plan/00` §九 的变更控制
重新评估需求基线、套餐和工期。

## 背景

`spec/01-产品需求.md` 已将媒体组聚合和跨身份媒体中转列为首发能力，`spec/02-总体架构.md`
也已给出跨身份中转方案。但 `eng/02-本地环境与迁移.md` 和 `plan/00-里程碑与工期.md`
仍保留“首发只转文本”的旧说明，导致首发范围、失败处置和验收口径不一致。

本决定只收口范围，不把现有 MinIO 容器、媒体数据模型或架构说明误记为媒体链路已经实现。
真实下载、上传、容量、caption 限制、对象清理和失败重试仍需在对应工作包中完成验证。

## 约束与影响

- 媒体组、跨身份中转、流式处理、`content_hash` 去重和对象存储保留期进入首发验收；
- pro 档单文件媒体上限继续沿用产品规格，不在本 ADR 中改价或改容量；
- 媒体 caption 的长度限制必须进入投递实现与反向测试，不能用截断原文代替；
- 文档、任务卡和验收标准必须统一为“首发包含媒体”；
- 媒体链路尚未实现，不得以本 ADR 作为实现完成证据。
