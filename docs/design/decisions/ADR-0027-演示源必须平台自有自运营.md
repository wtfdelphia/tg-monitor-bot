# ADR-0027：演示源必须是平台自有自运营的频道

状态：已定案

## 决定

演示源只能是**平台自己拥有并作为管理员运营的频道**。
拿第三方公开频道充当演示源，即使它公开可读，也不允许。

这条收紧 [[ADR-0014]] 正文里「演示源的内容是平台自己选的公开频道」的表述 ——
「自己选的」不等于「自己拥有的」，而这两者的法律含义完全不同。

## 背景

ADR-0014 废除官方 Bot 托管的理由是责任边界：平台无法验证租户对某个频道有权限，
一旦平台身份出现在采集链路上，平台就从「工具提供方」变成「内容访问方」。

演示源被当作这个问题的出路 —— 读取主体是平台自己，责任归属清晰。
但「平台自己选一个公开频道来读」并没有解决同一个问题，只是换了个主体：

- 平台对那个第三方频道同样没有授权。公开可读 ≠ 授权批量采集与再分发
- 平台把它的内容投递给租户，等于平台替租户做了 scraping ——
  而这正是 [[ADR-0015]]「定位为转发工具，不是聚合器」要避开的那条线
- 内容不可控：第三方频道发什么平台管不了，也无法下架。
  演示源出现违规内容时，责任在展示它的平台

自有自运营把这三条同时消掉：平台是该频道管理员，内容由平台决定、可下架，
采集的是自己的东西。代价是演示内容不真实（是平台自己造的流量），
但这个代价比授权问题小得多。

`spec/02-总体架构.md` 的演示源四条硬边界第 1 条已经是这个口径，
本 ADR 只是把决策依据补上 —— 原先 ADR 与 spec 的措辞是冲突的。

## 代价

- 演示源的内容要平台自己生产。真实感差，"看起来像个 demo"
- 多了一份持续运营负担：频道要有内容更新，否则演示效果是一条死流
- 演示价值受限：租户看到的不是自己关心的领域的真实消息，
  转化漏斗中间那一段缺口（ADR-0014 已列）因此更明显，而不是被缓解
