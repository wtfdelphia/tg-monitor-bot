# ADR-0039：恢复窗口与删除完成范围分离

状态：2026-10-28 维护人批准物理删除提案及整体留存衔接方案；本记录登记已批准语义，不代表删除代码或生产调度已实现。

## 决定

恢复窗口结束只使 deleted 租户进入到期候选，不承诺根行或所有副本即时消失。
共享引用未解除时保留必要 tombstone、身份及事件关系，不强删共享数据、不改挂身份，
也不延长恢复窗口或恢复业务访问、凭据。

区分到期候选、待清理/阻塞、执行失败和主库租户清理完成；只有批准范围内的数据与根行
均已删除后才能报告主库完成。共享媒体继续按全局规则留存，固定平台级完成日志沿用
系统日志期限；主库完成不代表全副本删除或底层介质安全擦除。

共享引用消失后由后续批次重新检查。没有自动到期条件的跨租户身份引用须报告人工核查，
不得假定重试一定成功。重试周期、阻塞告警与人工升级阈值、最长阻塞期限仍待定，
不在本记录补写具体时限。

ADR-0029 的不归档决定及两条同意记录级联外键保持不变。根行因共享引用暂留可能延长
同意记录的实际存活；清理不能在共享阻塞期间先删成员，借另一条级联路径提前清空同意记录。
租户审计与系统日志继续按既有分项期限回收，不因 tombstone 延迟而续期或冻结。
最终成员、同意记录及根行删除须满足限批与权限约束；做不到时升级，不绕过外键。
本决定补充 ADR-0029 代价节的时间边界：窗口结束不代表凭证必定已被删除，
实际不可恢复以完成清理为准；不修改旧 ADR 正文。

整体留存范围由生命周期规格登记，表级期限不在提案或本 ADR 重复。
备份、快照、恢复副本、Redis 关联元数据、运行日志、临时凭据文件和 Telegram 已投递内容
分别说明控制范围、现有规则与未定策略。备份淘汰、访问限制和恢复后防止已删除数据重新可用的
方案须在上线前单独定案并验收；当前不选择具体方案，不新增归档或永久删除登记表。

## 背景

租户根行经身份关联共享原始事件；其他租户的投影或配置仍有引用时，现有外键会拒绝删除。
这保护了引用方数据，但“窗口结束即级联全部删除”的描述没有覆盖这种情况。
强删共享事件会影响其他租户，改挂身份又会改变归属，因此保留受保护残留并报告阻塞。

表级清理不能证明备份、运行日志及外部分发副本同时消失。现有运维文档有备份恢复要求，
但没有已定的副本淘汰和恢复后维持删除状态方案；不能将未知副本默认为不存在或已经清理。

## 代价

引用可能长期不解除，根行与同意记录没有可承诺的最终删除时刻。
待清 tombstone 不计作该租户跨表无残留，自动重试也不能代替人工处理异常引用。
不改变既有外键并不等于限批清理已经可行，成员与同意记录的第二条级联路径仍须实测。

平台只能按已验证范围报告清理；不能把主库命令成功用作全副本删除证明。
恢复旧副本可能使已注销租户、会话或凭据重新可用，恢复流程须先核对并维持删除状态，
不能恢复后直接开放业务。后续策略与生产验收仍有工作，本记录不据此宣布生命周期全部完成。
