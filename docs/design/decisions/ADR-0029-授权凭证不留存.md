# ADR-0029：授权凭证随租户级联删，不留存

状态：**已定案**（2026-09-21）

## 决定

`tenant_consents` 保持现状：两条 `ON DELETE CASCADE` 都不动，
租户物理删除时授权凭证一并消失。**零 DDL 变更。**

这收掉了 `spec/04-数据生命周期与容量.md` 里那处「已知未决权衡」的二选一 ——
它是 [[ADR-0028]] 唯一的技术下游。

**但这是「推迟」，不是「放弃」。** 升级路径与触发条件写在下面的「代价」节，
那部分和决定本身一样承重。

## 背景

`spec/04` 把这件事登记为未决时给出的两个方向是：

```text
留存   → FK 改 ON DELETE SET NULL，并加 deleted_tenant_ref 冗余列
不留存 → 就是现状
```

**实测（PG 17.11，一次性容器）推翻了「留存」那条路的写法。**
`spec/04` 只考虑了指向 `tenants` 的那条 FK，
而 `tenant_consents` 有**两条** CASCADE，第二条是指向
`tenant_members` 的复合 FK，其 `tenant_id` 参与主键且 `NOT NULL`：

```text
A  单列 FK，NOT NULL 列上 ON DELETE SET NULL
   → CREATE TABLE 通过，DELETE 时才报 not-null violation
B  复合 FK，整组 SET NULL（tenant_id 也被置空）
   → CREATE TABLE 通过，DELETE 时才报 not-null violation
C  PG 15+ 的 ON DELETE SET NULL (user_id) 只置空列表里那一列
   → 可行。tenant_id 原值保留，行存活
D  同上，但 user_id 仍为 NOT NULL
   → CREATE TABLE 通过，DELETE 时才报 not-null violation
```

> **四种写法里三种是定时炸弹。** `CREATE TABLE` 全部成功，
> 错误只在第一次真实 DELETE 时出现 —— 与「`CHECK` 约束引用
> `current_setting` 建表时接受、恢复时失败」完全同类的形状。
> 这类形状在本项目里已经出现过两次，它们的共同点是
> **迁移跑绿不能证明约束是对的**。
>
> 顺带实测的一条：`RESTRICT` 挡下删除时整条语句原子回滚，
> 同一条 `DELETE` 上 `tenant_members` 的 CASCADE 不会留下部分删除的残骸。
> 这条对本决定没用（我们不走 RESTRICT），但它排除了
> 「注销失败会把数据搞成半拉子」这个顾虑。

选不留存的决定性事实是**审计日志的 FK 形状**：
`audit_logs.tenant_id` 同样是 `ON DELETE CASCADE`。
所以租户注销后归零的不是「凭证这一张表」，
而是平台对该租户的全部历史记录 —— 审计与凭证同时消失。
这反而是自洽的：不会出现「能证明租户做过什么、却证明不了租户授权过什么」
这种最难看的组合，举证能力是整体消失的。

另一条支撑事实：[[ADR-0016]] 已砍掉 enterprise 档，
首发阶段不存在会来问 DPA 与子处理者清单的企业客户，
事后异议的风险本来就处在最低点。
在这个时点花 DDL 预算去建举证能力，是为一个还不存在的客户群付费。

**选不留存而不是建归档表，关键在于方向是单向可走的**：
不留存可以之后升级成归档 —— 那是**新建一张无 FK 的表**加注销流程里的一步，
不动任何既有 DDL、不动 RLS 策略、不动建表铁律。
反过来，先建了归档表再想撤，要处理的是已归档数据的删除义务，
那是合规动作不是技术动作。所以低成本的那一侧同时也是可逆的那一侧。

## 代价

- **注销宽限期一满，那批凭证不可恢复。** 这是本决定唯一不能事后补救的部分：
  其他决策改主意只是改代码，这一条改主意救不回已经删掉的数据。
  升级成归档只对**升级之后**注销的租户有效。
- **平台对已注销租户的异议没有抗辩材料。** 诚实的说法是
  「数据已按删除义务清除，包括授权记录」——
  这在欧盟框架下是合规姿态而非缺陷（存储限制原则站在这一侧），
  但它不能用来自证平台曾获授权。
- **「推迟到第一个企业级异议出现前」必须是一个有人看着的条件，
  否则它就是无限推迟。** 触发升级的信号是下列任一项：

  ```text
  1 出现第一个要求 DPA 或子处理者清单的客户（即 enterprise 诉求复活，
    那同时也是 ADR-0016 的复审信号）
  2 收到第一次来自已注销租户的异议或投诉
  3 律师在 D4 剩余两项的答复中明确要求保留授权记录
  ```

  这三条都是外部事件，不是日历时间 —— 本决定**不设复审日期**，
  因为按日期复审在没有触发信号时只会被原样延期一轮。
- **`spec/04` 那处「未决权衡」的记述需要改写，而它写错了一半**：
  它给的「留存」方案只覆盖了指向 `tenants` 的 FK，
  漏了 `tenant_members` 那条复合 FK，
  而后者按它写的改法是跑不通的（见背景节实测 B/D）。
  将来真要升级时不能照着那段做。
