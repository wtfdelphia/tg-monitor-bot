# 决策记录（ADR）

**一决策一文件，只追加不修改。**

这是全库唯一「为什么」的归口处。`spec/` 说的是「是什么」，
`eng/` 说的是「怎么被强制」，两者都不解释为什么当初这么选 ——
一旦在那些文档里写理由，理由就会随文档改写而丢失。

---

## 规则

```text
1 一个决策一个文件，文件名 ADR-00XX-短标题.md
2 已定案的 ADR 正文不再修改。改主意的方式是写一份新的，
  并在旧的末尾追加一行「已被 ADR-00YY 取代」
3 编号只增不复用。删除一个 ADR 等于删掉一段历史，不做
4 spec/ 与 eng/ 引用 ADR，ADR 不反向依赖它们的章节号
  （章节号会飘，文件名不会）
5 第 2 条保护的是「决定 / 背景 / 代价」这三节 —— 也就是理由本身。
  指向其他文档的定位符（文件名、章节号）不是理由，修掉失效的定位符
  不算改主意，不需要新开 ADR
```

第 4 条是有意的不对称：ADR 里写「详见 `spec/03` §1.2」这种引用会在
`spec/` 改版时失效，而 ADR 的理由部分不允许改 —— 所以 ADR 里只提文件名与概念，
不提章节号。

第 5 条是第 2 条与第 4 条的交界处：早期有 13 份 ADR 写了章节号，
其中两处（ADR-0008 指 `spec/03` §4、ADR-0009 指 `spec/02` §2）在被发现时
**已经指不到任何现存标题** —— 正是第 4 条预言的失效模式。
它们已按第 5 条就地删去章节号，只留文件名。

模板：

```markdown
# ADR-00XX：标题

状态：已定案 / 未定案

## 决定
一句话。

## 背景
当时面对什么，有哪些选项。

## 代价
选了这条要付什么。不粉饰。

## 相关
[[ADR-00YY]]，以及落地在哪份文档。
```

「代价」一节不是形式：**没有代价的决策说明还没想清楚**，
那种情况下应该先想，不该先写 ADR。

### 第六条规则：「落地追记」是允许的第五节

```text
6 已定案的 ADR 可以追加一节「## 落地追记（日期）」，写在「相关」之后。
  它记的是这个决定被执行之后才知道的事：判据被加强、代价里的数字被
  实际落地推翻、原文没预见到的新代价。前四节一个字不动
```

这一条是规则 2 与「文档要能指导下一次动手」之间的出路。ADR-0022 是第一例：
它的代价一节写着「9 条 + 3 条补充断言」「A2 只查 `app_user`」「A7 只覆盖
三条白名单中的一条」，落地后实际是 16 条、A2 改成了派生、白名单减到两项。

**第四处「`eng/03` 的 42 条」我一开始也登记成过期了，是错的** —— 42 含
A/Q/X 三族，不是 R 的条数。追记节里留着这次返工的记录，因为它示范了
追记节自己也会写错：**追记不受规则 2 保护，正是为了能这样改回来。**

**为什么不按规则 2 写一份新 ADR 取代它**：那三节的理由（断言查状态而非 diff、
判据用列的存在而非人维护的清单、1 人团队下第二人复核是空话）一条都没变。
新写一份等于把没改主意的理由复制一遍，而复制出来的两份会各自漂移。

**为什么不就地改掉那些数字**：规则 2 的保护对象是「决定 / 背景 / 代价」，
而代价一节里的数字与理由是缠在一起的 —— 改数字很难不顺手改掉旁边那句为什么。
分节写，原文的每一句都还能被读成「当时是这么想的」。

追记节不受规则 2 保护，可以随后续落地继续改。它也不是索引表里的状态 ——
一份 ADR 有追记不代表它被取代。
