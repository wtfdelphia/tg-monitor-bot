# ADR-0028：司法辖区定为欧盟

状态：**已定案**（2026-09-21）

## 决定

目标市场辖区 = **欧盟**。合规口径按欧盟框架写（GDPR 类），
不做中国与美国的并行适配。

这收掉了 `spec/06-合规与凭据责任.md` 里 D4 的第 1 项，
也收掉了 `plan/01-风险登记.md` 的 RK-17。

## 背景

这个未决项悬了整个设计期，但它的爆炸半径比索引看起来小得多。
全库扫描的结果是：

```text
「中国 / 欧盟 / 美国」三选一的枚举   全库仅 1 处
GDPR                                 全库仅 1 处
欧盟 / PIPL / CCPA 作为已选方案      零处
ops/ 里的部署地域 / 数据驻留         零处
```

也就是说**文档集从未为任何一个辖区写过具体规则**。
定案欧盟是往空白处填，不是改写既有论述 ——
这是它能在此刻低成本定下来的原因，
也意味着真正的合规工作量一件都还没做，只是不再被「不知道按哪套写」挡住。

选欧盟的理由不是市场判断，是**它是三者中要求最高的那一套**：
按欧盟写，将来要进其他辖区是收缩要求而非新增要求；
反过来按中国或美国写，进欧盟等于重做。
在没有真实客户分布数据的阶段，选严格的那一侧是唯一不需要预测的选法。

> **但「按最严的写」这句话在本项目里有一个当下无法兑现的部分。**
> 数据驻留是欧盟客户最常问的一条，而 `ops/` 里**完全没有地域概念** ——
> 不是写错了，是从未写过。同时 [[ADR-0016]] 已砍掉私有化部署，
> 也就砍掉了「数据不出境」这个诉求唯一的现成答案。
> 定案欧盟并不能自动解决它，只是让它从「不知道要不要管」
> 变成「明确欠着」。落点在部署文档，不在本 ADR。

## 代价

- **平台自身的部署地域仍未定，而欧盟辖区让它从工程选项变成合规变量。**
  在此之前「部署在哪」只影响延迟与成本，定案之后它开始影响能不能签单。
  这一项由 `ops/` 承接，首发不解决。
- **D4 的另两项没有被这个决定收掉**：合法性基础（合同 / 正当利益）
  与删除请求的响应义务、以及避风港主张能否成立，仍然待律师。
  辖区定案只是让律师问题**可问**了 —— 在辖区未定时那两个问题根本无法提问。
- **法务工作量不在 263.9 人日内**（见 `plan/00-里程碑与工期.md` 的局限节）。
  本决定不改变这一点，它只是把「等辖区」这个借口拿掉了。
- 选了最严的一侧，意味着如果真实客户其实集中在非欧盟辖区，
  我们付了一份用不上的合规成本。这个赌注是有意的，理由见上。
