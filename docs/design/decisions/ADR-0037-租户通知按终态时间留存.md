# ADR-0037：租户通知按终态时间留存

状态：2026-10-26 维护人批准 `WP-8-notification-retention` 提案后实施。

## 背景

租户通知只有成功发送时间，没有永久失败的可靠结束时间。按入队时间删除，
会把长时间重试后刚送达或刚失败的记录当作旧记录清掉；只随身份或租户删除则无法限制终态积累。

## 决定

SENT 与 DEAD 从进入终态起保留同一窗口，期限以 `spec/04-数据生命周期与容量.md` 为准，
不按套餐区分。PENDING 不由终态留存清理，发送退避与身份失权入队事务不变。

新增 `terminal_at`，成功时与 `sent_at` 相同，永久失败时由数据库时间记录。
写入入口先锁定仍为 PENDING 的行，再以新语句记录结果，避免行锁等待时间使终态时间提前。
重复确认不刷新终态时间，清理后的确认不重建通知。
旧 SENT 保留其成功时间；旧 DEAD 无可证明的结束时间，保守地从首次迁移时重新起算，
重复迁移不刷新该值。CHECK 约束状态与时间形状，记录时间由受信应用入口负责，
不声称能防止有写权限的业务角色绕过入口执行任意 SQL。

复用独立租户清理身份与固定类别，只授候选元数据读取和受限删除，
不扩大发送进程的删除权限，也不授清理角色通知详情或凭据读取。
删除与固定清理日志同事务，调度与生产验收分开记录。

## 代价

旧 DEAD 的真实历史时间不可恢复，保守回填会延长其存活，不伪造历史时间。
迁移前须停止旧版通知发送循环，迁移后只启动新版，再启用清理；本片不保证新旧版本混跑。
身份或租户物理删除仍可提前级联清除通知，本规则不将通知变成独立合规凭证，
也不证明用户已阅读或实现通知 exactly-once。
