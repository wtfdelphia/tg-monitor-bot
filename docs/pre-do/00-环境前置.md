## 一、docker compose 插件没装（最严重）

这一项在 `../design/eng/02-本地环境与迁移.md` §一 的整节都以「有 compose」为前提，
而它不成立。

```text
docker --version                       Docker version 29.1.3          ✓ 在
docker info --format {{.ServerVersion}} 29.1.3                          ✓ daemon 在
docker pull postgres:17-alpine          Downloaded newer image          ✓ 拉得到
docker run --rm postgres:17-alpine postgres -V
                                        PostgreSQL 17.11                ✓ 满足安全下限

docker compose version                  docker: unknown command         ✗
docker-compose --version                command not found               ✗
~/.docker/cli-plugins/                  No such file or directory       ✗
/usr/libexec/docker/cli-plugins/        只有 docker-trust               ✗
find / -name 'docker-compose*' -type f  无任何二进制                    ✗
```

镜像里的 PG 实测 **17.11**，正是 `../design/eng/00-工程约定.md` §二 所要求的
CVE-2026-14666 修复版本下限 —— 所以镜像选型是对的，缺的只是编排工具本身。

**为什么这一项排第一**：`../design/eng/02-本地环境与迁移.md` §3.2 把
「迁移失败的处置」定义为本地 `docker compose down -v` 从零重建。
也就是说 compose 既是起库的唯一方式，也是失败恢复的唯一方式。
没有它，动工顺序的第 4 步之后全部无法执行。

**推论**：`../design/eng/02-本地环境与迁移.md` §七 记了「MinIO / Redis 的 compose 片段未实测启动」。
现在知道原因了 —— 不是这两个片段没验，是**整份 compose 从未跑过**。
PG 与 PgBouncer 的实测结论来自手工起容器，不来自编排。

**修复**：apt 有候选。

```text
docker-compose-v2   2.40.3+ds1-0ubuntu1~22.04.1   ← 这个，提供 docker compose 子命令
docker-compose      1.29.2-1                       ← v1，已停止维护，不要用
```

> **判据**：`docker compose version` 有输出。
> 不要用 `docker-compose --version` 验证 —— 那验的是另一个程序。

**复测：已解除。** `docker compose version` → `Docker Compose version v5.5.1`。
装的不是上面那个 apt 候选，版本号也比它高得多，所以别照抄那两行 apt 包名当结论。
`compose.yaml` 已提交并实际起过库：迁移与 `tgm audit-rls` 都是在这套编排起的库上跑的
—— 也就是说 §七 那条「整份 compose 从未跑过」的推论随之作废。

> 一处仍需留意，不影响判据：docker daemon 曾在 2026-09-21 23:35:49 失败一次后自愈。
> 只出现过一次，没有复现，不作为阻塞项登记 —— 再出现要查 daemon 日志而不是 compose。

## 二、psql 在非交互 shell 里不存在

```text
bash -ic 'psql -V'    psql (PostgreSQL) 17.11 (Ubuntu 17.11-1.pgdg22.04+2)   ✓
bash -lc 'psql -V'    bash: psql: command not found                          ✗
```

根因在 `~/.bashrc` 的行序：

```text
15   # If not running interactively, don't do anything
16   case $- in
19   esac                                    ← 非交互到这里就 return 了
...
160  source "$HOME/opt/pgdg17/env.sh"        ← 永远到不了
```

PG 17.11 是用户级安装（`~/opt/pgdg17/`），不是系统包，所以 PATH 完全依赖这一行 source。

**影响面比 CI 大。** `../design/eng/00-工程约定.md` §零 写的是
「psql 17.11 ✓ 已装……env.sh 已挂进 ~/.bashrc」，并正确推出了 CI 里要显式装 psql 的后果。
但同一个早退也命中所有本地非交互执行路径：Makefile、迁移脚本、
`cargo sqlx prepare`、`tgm audit-rls`、compose 的 healthcheck 包装脚本。
文档推对了一半。

还有一处连带：`../design/eng/02-本地环境与迁移.md` §一 的 healthcheck 用
`psql -U postgres -d tgm -c 'SELECT 1'`。那条在**容器内**执行，用的是镜像自带的 psql，
不受本机 PATH 影响 —— 这条不用改，但容易误判成同一个问题。

**修复**：把 `source env.sh` 移到 `~/.bashrc` 早退之前，或改写进 `~/.profile`。

> **判据**：`bash -lc 'psql -V'` 有输出。
> 在此之前不要相信任何「本地能跑」的结论，也不要用 `bash -lc` 包 psql 去验迁移。

**复测：已解除。** `bash -lc 'psql -V'` → `psql (PostgreSQL) 17.11 (Ubuntu 17.11-1.pgdg22.04+2)`。
改法是把 `source "$HOME/opt/pgdg17/env.sh"` 提到第 15 行，即早退的 `case $-`（第 22 行）之前。

> 但这条只解除了「登录 shell」。**非交互非登录的调用路径仍然需要显式 source** ——
> 本次实测的每条 psql 命令前面都带着 `source "$HOME/opt/pgdg17/env.sh"`。
> 换句话说本项修的是判据那一种形状，不是全部形状；CI 里照样得显式装 psql。

## 三、三个 cargo 子命令缺失

```text
cargo --version          cargo 1.98.1 (797e8a9bc 2026-08-05)   ✓
rustc --version          rustc 1.98.1 (48a229cea 2026-09-01)   ✓

cargo sqlx --version     error: no such command: `sqlx`        ✗
cargo deny --version     error: no such command: `deny`        ✗
cargo audit --version    error: no such command: `audit`       ✗
```

这三个对应 `../design/eng/04-CI门禁.md` §四 卡口命令清单 里的三条，缺一条就少一道卡口。

registry 可达，已实测 `cargo search` 能查到当前版本：

```text
sqlx-cli      0.9.0     与 eng/00 §二 钉的 sqlx 0.9 同线
cargo-deny    0.20.2
cargo-audit   0.22.2
```

`~/.cargo/config.toml` 不存在，即没有配镜像源，走的是官方 registry。

> **判据**：三个命令 `--version` 都有输出。
> `sqlx-cli` 装的时候注意 features —— 只需要 postgres，默认会带上别的驱动。

**复测：已解除。** 三条都有输出，版本与上面 `cargo search` 查到的一致：
`sqlx-cli-sqlx 0.9.0` / `cargo-deny 0.20.2` / `cargo-audit-audit 0.22.2`。

> `cargo sqlx prepare --check` 光装上还不够，它有两个参数陷阱
> （`--workspace`、只认 `DATABASE_URL`），见 `../design/eng/04-CI门禁.md` §四。
> 少任一个这条卡口就是空的绿灯 —— 那正是 `03-文档待更正.md` 八 登记的事。
